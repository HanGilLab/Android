# 준비한 코스의 고정 시연 지점 지도

저장된 준비의 목표, 코스, 과제 ID와 코스/브리핑 버전을 현재 카탈로그에 대조한 뒤 해당 코스의 지도 미리보기를 표시한다. `생활권 한 바퀴`는 서울 시청 주변, `교차로 흐름 익히기`는 광화문 주변의 공개 장소 표시점을 사용한다. 두 코스의 설명과 과제는 허구의 준비 예시이며 실제 주행 검토를 마친 코스가 아니다.

이번 연결은 MAP-02 중 준비한 코스에 맞는 고정 시연 지점을 표시하는 부분이다. 실제 도로 구간, 출발/도착 지점과 주행 가능성 검토, 길안내, 세션별 실제 이동 지도는 별도 미완료다. 이 기능만으로 MAP-01 또는 MAP-02 전체를 완료로 기록하지 않는다.

## 표시점의 정의와 출처

출처는 `FIXED_OSM_BOUNDING_BOX_CENTERS`다. 공개 OpenStreetMap(OSM) way의 전체 geometry에서 위도와 경도의 최솟값/최댓값을 각각 구한 뒤 경계 상자의 중심을 계산했다. 확인 기준은 2026-10-30 11:56:20 UTC이며 카탈로그 좌표는 소수점 일곱 자리로 반올림한 고정값이다.

```text
표시 위도 = round((최소 위도 + 최대 위도) / 2, 7)
표시 경도 = round((최소 경도 + 최대 경도) / 2, 7)
```

이 계산값은 건물이나 장소의 출입구, 도로 위 지점, 차량 목적지 또는 다각형 내부점임을 보장하지 않는다. 화면의 번호는 시연 목록의 순서다. 번호 사이에 이동 선을 그리지 않으며 방문 순서, 연결 도로, 거리, 소요 시간이나 이동 가능성을 뜻하지 않는다. SDK 위치, GPS와 사용자 이동 자료는 이 표시점에 사용하지 않는다.

## 준비, 렌더와 잠금 경계

실시간 P와 UX 허용을 모두 확인해야 저장된 준비를 구독하고 상세 지도를 표시한다. 준비 로딩, 빈 준비, 오래된 ID/버전, 조회 실패와 지도 자료가 없는 코스를 각각 구분한다. 조회 예외나 비정상 스트림 종료를 빈 준비나 기본 시청 지도로 바꾸지 않는다.

카탈로그에서 받은 선택과 표시 내용, 조회 수명주기가 달라지면 렌더 시도를 갱신한다. 이전 View의 렌더 완료/실패 콜백으로 새 코스의 상태를 바꾸지 않는다. 준비 재시도는 새 조회 epoch를 사용하고 이전 결과를 버린다. 지도 렌더 재시도와 준비 조회 재시도는 별개다. 닫기와 수명주기 이탈 시 준비 구독을 정리하고 다시 들어올 때 현재 준비를 읽는다. 아직 저장소가 방출하지 않은 변경을 동기적으로 감지하는 계약은 아니다.

표시점은 `LocalPracticeCatalog`의 현재 자료에서 읽고 MapLibre의 별도 GeoJSON source, 원과 번호 레이어로 표시한다. 지도 카메라는 선택한 표시점들을 담도록 설정한다. 사용자의 준비, 세션, SDK 차량 관찰과 메모를 지도 열람 때문에 수정하지 않는다. 새 DB 스키마나 위치/내비 권한을 추가하지 않는다.

## 실제 앱 검증 절차

아래는 수행할 절차다. 이 문서 자체는 실행 성공이나 검증 완료의 근거가 아니다. 실제 결과, 실패한 시도, 건너뜀과 미실행은 해당 작업 계획과 PR에 구분해서 기록한다.

1. 같은 checkout과 전용 AVD를 사용하는 살아 있는 작업이 없는지 확인한다. 기존 활성 세션이 있거나 원래 준비가 비어 있으면 현재 명시적 시나리오를 시작하지 않는다. 기존 준비, 세션, 관찰, 메모와 권한/기어/UX/글꼴/야간 설정을 비공개로 보존한다.
2. JDK 17을 선택하고 전체 검사와 `:app:assembleDebugAndroidTest`를 먼저 수행한다. 무거운 Gradle과 Pleos 실기는 순차 실행한다. 기존 앱 데이터 삭제나 추가 권한 부여 없이 전용 debug 앱과 계측 APK를 설치한다.
3. 실제 브라우저의 DDS 제어 브리지와 앱 SDK에서 P 및 UX 허용을 확인한다. 실제 전면 앱과 화면을 확인하고 기본 내비나 카메라 오버레이가 가리지 않게 한다. HTTP 응답이나 빈 UI 계층만으로 준비 완료를 판단하지 않는다.
4. 아래 명시 옵션으로 `PreparedCourseMapFlowTest`를 실행한다. 장치 선택, 원문 로그와 검사 소유 기록은 비공개로 관리한다.

   ```sh
   adb shell am instrument -w -r \
     -e manualPreparedCourseMap true \
     -e class io.github.hangillab.hangil.PreparedCourseMapFlowTest#preparedCoursesReplaceNativePointsAndKeepDataAcrossLifecycleAndDrivingLock \
     io.github.hangillab.hangil.debug.test/androidx.test.runner.AndroidJUnitRunner
   ```

5. 두 코스를 차례로 준비하고 실제 MapLibre의 GeoJSON source, 지점 좌표/번호, 원/번호 레이어와 카메라를 카탈로그에 대조한다. 지도 화면을 연 채 코스를 바꾸고 새 지역과 표시점이 반영되는지 확인한다. 제목이나 Compose의 준비 상태만으로 실제 지도 렌더 성공을 대신하지 않는다.
6. 재생성, 닫기/재진입과 실제 DDS의 D/P 전환에서 지도 제거/복귀를 확인한다. `PREPARED_MAP_AWAIT_D`와 `PREPARED_MAP_AWAIT_P` 단계에서 외부 실행자가 기어를 제어한다. 기본 글꼴 1.0의 라이트와 확대 글꼴 1.3의 다크에서 표시점, 출처, 번호 목록과 버튼 도달을 실제 화면으로 확인한다. 글자를 줄여 내용을 맞추지 않는다.
7. 검사에서 일시 선택한 준비만 소유 근거에 따라 원래 값으로 복구한다. 모든 세션, 관찰과 메모의 전체 필드를 대조하고 원래 권한과 설정을 확인한다. 복구를 확정하지 못하면 소유 기록을 보존하고 성공으로 기록하지 않는다. 사용자의 새 변경이나 다른 작업의 자료를 덮지 않는다.

지도 오류/재시도는 실제 오류와 주입한 오류를 구분한다. 기본 실행의 건너뜀은 통과가 아니며 지점 표시 확인을 실제 주행, 위치 수신, 도로 검토 또는 길안내 검증으로 확대하지 않는다. 공개 캡처는 검증이 끝난 실제 앱 영역만 사용하고 기기 정보, 계정, 개인 경로, 사용자 위치와 원문 로그는 포함하지 않는다.

### 제어된 지도 타일 오류와 재시도

`PreparedCourseMapFlowTest#injectedRemoteTileFailureRetriesPreparedPreviewWithoutDataChanges`는 `manualPreparedMapNetwork=true`로만 실행한다. 먼저 정상 준비 지도가 실제로 렌더됐는지 확인하고, 도달 불가 프록시를 주입한 뒤 공개 표시점에서 위경도 각각1도 떨어진 합성 카메라로 다른 지역의 타일을 요청한다. 이 좌표는 오류 재현용 입력이며 사용자 위치, 코스 데이터나 실제 주행 결과가 아니다. 실행자는 해당 타일의 공식 서버 정상 응답을 기기 밖에서 먼저 확인하며 기기 캐시는 지우지 않는다.

동일 source/z/x/y에서 실제 `RequestedFromNetwork`와 `Error`가 순서대로 관찰되고 오류/재시도 UI가 나타나야 주입 오류를 확인한 것으로 판단한다. 연결 복구와 명시적 재시도 뒤에는 원래 코스의 source, 표시점과 카메라를 다시 검사한다. 원래 프록시 값과 네트워크 경로, 준비와 기존 세션/관찰/메모를 최종 대조한다. 셸 실행에 전달할 프록시는 쓰기 전에 안전한 단일 인자 형식인지 확인한다. 임의 프록시 형식을 따옴표로 추측해 재구성하지 않는다.

이미 불러온 지도에 프록시만 설정한 실행에서 오류가 나타나지 않으면 오류 검증 통과로 기록하지 않는다. 위 절차는 실제 SDK의 제어된 실패 경계 확인이며 자연 발생한 통신 장애, 성능 개선이나 실제 도로 검증으로 확대하지 않는다. 합성 카메라 화면은 공개 기능 캡처에 사용하지 않는다.

## 성능 자료의 범위

기준 앱에는 저장된 준비 코스별 지점을 표시하는 동등한 실행 경로가 없었다. 이번 변경은 새 제품 연결이므로 전후 성능 개선이나 개선율을 주장하지 않는다. 별도 병목을 발견하면 코드 변경 전에 [전후 측정 기준](measured-improvements.md)에 따라 기준 커밋, 지표, 조건과 반복 표본부터 정한다.
