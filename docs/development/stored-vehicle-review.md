# 최근 종료 세션의 차량 관찰 확인

홈의 최근 마무리한 연습에서 `기록 자세히`를 펼치면 저장된 차량 관찰을 확인한다. 기본은 마지막 관찰이며 이전/다음 버튼은 저장 ID 증가 순서를 따른다. 앱 관찰 시각이 역행해도 시각으로 정렬하지 않는다. 한 화면에 긴 이벤트 목록을 나열하지 않고 한 스냅샷의 당시 연결, 기어, 방향지시등과 브레이크를 크게 보여 준다.

## 출처와 한계

코스의 시연 배지와 저장된 SDK 관찰 출처를 구분한다. 관찰 시각은 앱이 상태를 관찰한 시각이며 SDK 이벤트의 발생 시각이나 각 값의 개별 수신 시각이 아니다. StateFlow는 중간 상태와 동일 상태를 생략할 수 있으므로 전체 주행, 모든 조작과 조작 횟수를 재현하지 않는다. 위치와 실제 경로, 운전 능력 평가, 구간별 지도와 메모는 제공하지 않는다.

Available의 실제 false/OFF와 Unknown, Unsupported, PermissionDenied, Error를 구분한다. 빈 기록, 조회 실패와 최근 세션 변경을 각각 안내한다. 조회 오류나 손상을 빈 목록/정상 상태로 바꾸지 않는다. 요청 세션과 다른 행, 양수가 아닌 ID/시각과 비증가 ID는 오류로 전달하며 임의 복구하지 않는다.

## 조회와 잠금 경계

실시간 차량 P와 UX 허용을 모두 확인한 경우에만 읽는다. 상세를 펼친 동안 하나의 cold Flow를 수명주기에 맞춰 구독하며 접기, 화면 이탈과 주행 잠금에서는 구독을 취소한다. 최근 종료 세션 ID가 요청 ID와 다른 경우 이전 기록을 다른 연습에 표시하지 않는다. 재시도와 이전/다음 콜백은 현재 차량과 UX 상태를 다시 확인한다.

기존 SDK 수집기, Room 스키마와 저장 행은 변경하지 않는다. 열람 기능에는 append/start/finish를 호출하는 경로가 없다. 내부 읽기 취소/예외/정상 Flow 종료는 실패로 표시하며 부모 수명주기 취소는 전파한다. 재시도는 이전 조회 취소가 끝난 뒤 새 조회를 시작한다.

## 명시적인 실제 기록 실기

`StoredVehicleObservationFlowTest`는 기본 실행에서 건너뛰며 아래 조건을 갖춘 외부 실행자의 명시 옵션에서만 실행한다. 건너뜀은 통과가 아니다.

1. 다른 살아 있는 작업이 전용 AVD/checkout을 사용하지 않는지 확인한다. 기존 AVD와 사용자 데이터를 재사용하고 원래 기어/UX/글꼴/야간/권한 및 DB 전체 행을 비공개로 보존한다.
2. Activity를 실행하기 전에 기존 활성 세션이 없는지 확인한다. 있으면 검증을 중단하고 사용자 연습을 임의 종료하지 않는다. 최근 종료 세션에는 이미 실제 SDK를 통해 저장한 P/D 관찰이 있어야 하며 검증을 위해 가짜 행을 만들지 않는다.
3. JDK17의 전체 검사와 `./gradlew :app:assembleDebugAndroidTest`를 먼저 마친 뒤 debug 앱과 계측 APK를 데이터 삭제/새 권한 부여 없이 설치한다. 무거운 Gradle과 실기는 순차 실행한다.
4. 실제 브라우저의 Virtual Console DDS 브리지가 연결되고 P 제어가 SDK로 수신되는지 확인한다. 재부팅 뒤 기본 내비가 전면이면 실제 앱 전면과 화면을 확인한다. 빈 UI 계층이나 HTTP200만으로 준비 완료를 판단하지 않는다.
5. 전용 debug 앱에서 아래 계측 메서드를 실행한다. 실제 장치 선택과 출력은 비공개 실행 기록에서 관리한다.

```sh
adb shell am instrument -w -r \
  -e manualStoredReview true \
  -e class io.github.hangillab.hangil.StoredVehicleObservationFlowTest#storedSdkSnapshotsAreReadOnlyAcrossDetailsLifecycleAndDrivingLock \
  io.github.hangillab.hangil.debug.test/androidx.test.runner.AndroidJUnitRunner
```

`STORED_REVIEW_AWAIT_D`에서 브라우저 DDS를 D로 바꾸고 실제 SDK/상세 잠금을 확인한다. `STORED_REVIEW_AWAIT_P`에서 원래 P로 복원하고 접힌 상세를 다시 연다. 방향지시등을 바꿀 필요가 없으며 카메라 오버레이가 전면을 가리지 않는지 실제 화면을 확인한다.

계측은 실제 저장된 모든 스냅샷의 저장 순서, 기어, 방향지시등, 브레이크, 연결, 앱 관찰 시각과 출처를 대조한다. 접기/재열기, 재생성, CREATED/RESUMED와 P/D 전환 전후 준비/세션/관찰의 모든 필드가 불변인지 검사한다. 외부 실행자는 실패 시에도 원문 근거를 보존하고 기어/설정을 복원해야 한다. 테스트가 SDK를 별도로 구독해 기어 수신을 확인하므로 제품의 모든 SDK 구독 해제를 입증하는 검사는 아니다.

빈 기록과 손상/미지원 fixture 회귀를 실제 SDK 실기와 구분한다. 최근 세션에 실제 빈 기록이나 오류가 없으면 해당 상태의 실제 SDK 재현을 통과로 기록하지 않는다. 기존 자료를 수정해 조건을 만들지 않는다.

## 기록과 README

원문 DB, ID, 실제 환경과 기기 정보, 원본 캡처와 로그는 ignored 비공개 기록으로 관리한다. 공개 화면은 실제 검증이 끝난 앱 영역만 자르고 메타데이터를 제거한다. 실패한 시도와 최종 통과, 기본/확대/다크의 실행 조건을 계획과 PR에 구분한다.

이는 새 열람 기능이며 동일 동작의 전후 성능 비교가 없어 개선율을 주장하지 않는다. 회귀 테스트 수와 저장 행 수를 성능 수치로 쓰지 않는다. 기존 README 대표 4개는 더 강한 문제 해결 근거가 있을 때만 교체하며 검증 목록과 테스트 수를 README에 추가하지 않는다.
