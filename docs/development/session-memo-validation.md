# 최근 종료 세션의 사용자 메모

최근 마무리한 연습의 `내 메모`에서 짧은 문장을 저장/수정하고 명시적으로 지울 수 있다. 메모는 직접 입력한 내용이며 SDK 관찰이나 운전 평가가 아니다. 원문과 빈 기록/조회 실패, 저장된 내용과 미저장 초안을 구분한다. 최대280 Unicode code point를 허용하고 공백뿐인 내용, NUL과 고립 surrogate를 거부하며 임의 trim/내용 정규화는 하지 않는다.

## 쓰기와 확인 경계

현재 P와 UX 허용을 모두 확인하고 최근 종료 세션에만 쓴다. 쓰기 전후에 같은 트랜잭션 안에서 조건을 다시 확인하며 잠금 시 롤백한다. 취소/SQL 실패/충돌을 저장 성공으로 바꾸지 않는다. 최신 종료 세션과 변경 토큰을 확인하고 버전은 벽시계 대신 새 opaque 토큰을 사용한다.

삭제 확인은 화면에서 본 토큰을 고정한다. 확인 중 새 저장본이 수신되면 창을 닫고, 늦게 남은 확인 콜백도 원래 토큰으로만 요청해 새 내용을 지우지 못하게 한다. 충돌 후 초안은 보존하며 취소 버튼이 신선한 재조회 조건을 해제하지 않는다. 저장본을 다시 읽어 초안을 버리는 동작은 별도 버튼으로 명확하게 표시한다. 빈 입력은 자동 삭제하지 않는다.

편집기는 펼친 주차 상세의 수명주기에 맞춰 읽고 같은 세션의 초안을 VM에서 유지한다. reader Job, action nonce와 revision이 IO의 commit callback에서도 유효해야 하며 닫힘/STOP/D 뒤 같은 세션에 재진입해도 이전 callback을 다시 허용하지 않는다. 저장 중 Room 자체 emit을 외부 충돌로 오인하거나 새 세션에 이전 결과를 섞지 않는다. 저장 성공은 실제 저장 결과 이후에만 표시한다.

키보드가 열린 동안 스크롤 viewport가 IME inset을 피하도록 구성하고 기존 Scaffold inset 소비를 반영한다. IME 높이, 포커스와 입력창 크기 변화 뒤 레이아웃 프레임에 맞춰 실제 편집기를 `BringIntoViewRequester`로 다시 보이게 한다. 잠금/편집 종료/화면 이탈에서는 포커스와 IME를 숨긴다. 기본 글자와 확대/다크에서 입력창과 저장 버튼에 실제 도달할 수 있는지 검증한다. [Compose inset 기준](https://developer.android.com/develop/ui/compose/system/insets-ui)을 참고하되 실제 Pleos 지원 여부는 실행으로 확인한다.

## 원본을 전진하기 전의 검증 순서

1. 현재 main/진행 계획/다른 살아 있는 채팅 및 lease를 확인한다. 기존 AVD, 앱/DB 전체 행과 권한/글꼴/야간/키보드 표시 설정을 비공개로 보존하고 활성 연습이 있으면 임의 종료하지 않는다.
2. 무거운 Gradle은 JDK17로 먼저 실행한다. 제품 앱 v4를 설치하거나 실행하기 전에 기존 v3 DB의 일관된 복사본을 만든다. WAL을 무시한 단일 파일 복사나 자료 삭제로 검사를 대체하지 않는다.
3. 격리된 database.test 패키지에만 복사본을 제공한다. `SessionMemoStorageTest.privateVersionThreeCopyMigratesWithoutChangingExistingRows`를 `allowPrivateVersionThreeMemoCopy=true`로 실행해 기존3테이블/sequence의 모든 값/물리 타입/ID/순서 보존, v4 메모0개와 외래키 오류0을 확인한다. 기본 발견 실행의 건너뜀은 통과가 아니다.
4. 복사본 보존 검사가 성공한 경우에만 debug 앱을 데이터 삭제/새 권한 없이 업데이트한다. 실제 제품 DB가 v4로 전진한 뒤에도 같은 원본 행과 sequence 및 메모0개를 별도로 확인한다. 예상하지 못한 실패가 있으면 근거와 백업을 보존하며 임의로 원본을 덮어쓰거나 다운그레이드하지 않는다.

## 실제 앱 입력과 두 프로세스 검증

`SessionMemoFlowTest`는 `manualMemo=true`를 명시한 전용 debug 앱에서만 실행한다. 실제 브라우저 DDS 브리지와 SDK의 P 수신, 전면 앱을 확인하고 기본 내비/카메라 오버레이/빈 계층을 앱 복원 성공으로 해석하지 않는다. 키보드 표시를 확인하기 위해 필요한 표시 설정만 원래 값과 구분하고 복원하며 새로운 입력기나 권한을 임의 설치/허용하지 않는다.

첫 메서드 `createEditAndLockMemo`는 기존 준비/세션/관찰/메모의 모든 값을 검사 앱의 비공개 소유 cache에 보존한다. 미완료 소유 기록이 있으면 새 작업을 중복 시작하지 않는다. UI를 통해 새 검사 소유 연습을 시작/종료하고 그 세션에만 일반적인 검증 문구를 입력한다. 실제 IME 표시와 Compose IME commit 입력을 확인하며 실제 사람의 키 탭이나 실제 주행 메모로 과장하지 않는다. IME가 열린 뒤 검사가 추가 스크롤을 해 입력창 문제를 숨기지 않고, 포커스/전체 노드 크기/클리핑과 실제 native 가용 viewport를 함께 비교한다. 빈 입력창과 다섯 줄 초안의 전체 가시성을 확인하고 저장/복원 캡처에서는 출처/본문/수정/삭제가 함께 보여야 한다.

`MEMO_AWAIT_D`에서 DDS를 D로 전환해 상세/IME 숨김과 DB 미저장을 확인하고 `MEMO_AWAIT_P`에서 P로 복원해 초안/저장본 구분을 확인한다. 명시적 저장/편집 취소/수정과 실제 토큰 변경, 재생성을 검사한 후 `MEMO_AWAIT_PROCESS_RESTART`와 소유 상태를 남긴다.

외부 실행자는 해당 앱 프로세스를 실제 종료한 뒤 두 번째 메서드 `restoreAndDeleteMemoAfterProcessRestart`를 별도로 실행한다. 소유 PID가 달라야 하며 같은 메모/토큰과 기존 자료를 다시 읽어야 한다. 삭제 취소와 명시적 확정은 검사 소유 메모에만 적용한다. 새 저장본 수신 후 옛 확인 콜백을 제어해 재생하는 경우에는 실제 SDK나 사람의 조작으로 표현하지 않고 동시성 경계 주입으로 분리한다. 원래 자료는 바꾸지 않으며 성공 때만 본인이 만든 소유 cache를 정리한다.

미저장 종료 단계의 가시성 실패는 `resumeUnstoredMemoAfterVisibilityFix`를 `manualMemo=true`, `resumeUnstoredMemo=true`로 명시 선택해 같은 검사 소유 세션에서 이어갈 수 있다. schema/producer/nonce/종료 단계와 최신 소유 세션/관찰/메모 없음 및 원래 자료의 전 필드 일치가 선행 조건이며 새 연습이나 메모로 덮어쓰지 않는다. 재시작 대기 직전에 현재 실행 PID를 기록해 후속 복원이 다른 프로세스여야 한다.

실패 시 cache/원본 증거를 보존하고 현재 기어/설정 및 검사 소유 세션을 확인해 안전하게 인계한다. 소유 ID가 확인되지 않은 사용자 연습이나 메모를 정리하지 않는다. 검사가 만든 종료 세션과 SDK 관찰은 남기고, 원래 모든 행/메모/권한/설정이 보존됐는지 readback으로 확인한 뒤 소유 AVD/포워딩/임시 콘솔만 종료한다.

## 결과의 해석

격리 fixture/가짜 저장소의 제어된 경합, 실제 v3 복사본 보존과 제품 UI/IME 검증을 구분한다. 독립 UX 제한/실제 플랫폼 오류 주입의 미지원은 일반 P/D 성공으로 대체하지 않는다. 새로운 메모 기능은 동등한 변경 전 실행 경로가 없어 전후 성능 개선율을 주장하지 않는다. 실제 결과와 실패/미실행/남은 조건은 계획과 PR에서 추적하고 README에 회귀 집계를 추가하지 않는다.
