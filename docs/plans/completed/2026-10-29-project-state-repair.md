# 프로젝트 이력 복구와 현재 기준 재검증

- 상태: 완료
- 요구사항: 현재 프로젝트의 꼬인 상태 정리와 디자인 개선 할 일 등록

## 목표와 범위

로컬 main과 원격 main의 이력 불일치를 정리하고 최신 코드의 품질, 테스트와 빌드를 확인한다.
기존 로컬 커밋은 복구용 브랜치에 보존하고 원격 main이나 진행 중인 다른 PR의 이력은 변경하지 않는다.
Homebrew JDK 17이 시스템 검색에 나오지 않을 때 설치된 런타임을 선택하는 검증 안내를 보완한다.
디자인 개선은 기존 기획의 할 일에 반영하며 이번 작업에서 제품 화면을 변경하지 않는다.

## 완료 조건

- [x] 미커밋 변경이 없는지 확인하고 기존 로컬 이력을 복구 가능한 브랜치로 보존한다.
- [x] 원격 main을 갱신하고 로컬 main이 같은 커밋을 가리키도록 동기화한다.
- [x] 기존 디자인 할 일에 사용자 피드백과 관찰 가능한 완료 기준을 반영한다.
- [x] 설치된 Homebrew JDK 17을 선택하는 문서 명령을 실제 확인한다.
- [x] 최신 기준의 전체 자동 검증과 테스트 결과를 확인한다.
- [x] 이 작업 PR의 CI와 Codex 리뷰를 확인하고 지적을 처리한다.

## 구현 단계

1. 로컬 상태, 원격 이력과 현재 계획을 확인한다.
2. 기존 main을 복구용 로컬 브랜치로 보존한 뒤 origin/main에서 main을 다시 만들고 ff-only 동기화한다.
3. 최신 main의 별도 작업 브랜치에서 전체 검증을 실행하고 실제 결함만 수정한다.
4. 결과와 남은 문제를 기록하고 PR 리뷰를 확인한다.

## 남은 문제와 인계

기존 이력을 담은 복구용 브랜치는 로컬에서만 보존한다. 이력이 정리되기 전의 비공개 기획 참조를 다시 공개하지 않는다.
진행 중인 위치 권한 검증 PR과 독립 UX 조합의 플랫폼 제약은 이번 이력 복구로 완료 처리하지 않는다.
디자인 개선 구현과 새 앱 화면 수동 검증은 이번 작업 범위에 포함하지 않는다.
기본 JDK 검색 실패와 daemon 첫 시작 메시지는 최종 전체 검증 성공과 구분해 남긴다.
