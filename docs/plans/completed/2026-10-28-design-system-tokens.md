# 공통 디자인 토큰과 민트 다크 테마

- 상태: 완료
- PR: [공통 디자인 토큰과 민트 다크 테마 #13](https://github.com/HanGilLab/Android/pull/13)
- 요구사항: 공모전 체크리스트 DES-04 (비공개 작업 명세)

## 목표와 범위

현재 main의 홈, 세션, 목표/코스, 브리핑, 지도에 쓰는 공통 치수, 간격, 타이포, 모서리, 아이콘 크기를 이름 있는 토큰으로 통일한다.
라이트의 기존 배치, 주요 행동, 페이지/일반 글자색을 유지하고 기본 진단 카드/보조 글자색은 녹색 역할로 통일한다.
다크의 기본 보라색 컨테이너, 대응 글자색도 민트/초록 계열로 명시한다.
색만으로 선택, 오류, 잠금을 표현하지 않고 기존 문구, 선택 표시, 접근성 semantics와 P+UX 잠금을 보존한다.
장면 일러스트, 전체 화면 재디자인, 새 공통 상태 컴포넌트는 DES-03/05/06 범위다.
미병합 위치 PR #10의 패널은 이 main 기준 밖이며 이후 main 통합 때 토큰으로 이식한다. 위치 권한 동의 대기는 변경하지 않는다.

- [x] 현재 main 화면의 반복된 스타일 치수가 같은 토큰을 사용하며 순서, 버튼 동작, 저장 내용은 유지된다.
- [x] 라이트와 다크 실사용 글자색 쌍과 선택 마커의 대비를 수치로 검증하고 미지원/실패를 정상값으로 표현하지 않는다.
- [x] 실제 Pleos에서 라이트와 다크와 확대 글꼴의 홈, 목표/코스, 브리핑, 지도 앱 프레임을 확인하고 잘림, 가림을 점검한다.
- [x] 다크의 P→D→P 잠금, 제목, 복원과 DB 보존을 확인하고 시험한 테마/글자 크기 설정을 원래 값으로 복원한다.
- [x] JDK 17 전체 검사, 관련 수동 검증, 코드 커밋의 PR CI와 Codex 리뷰를 통과한다. 최종 문서 커밋의 검사, 리뷰도 병합 전에 별도 확인한다.

## 구현 단계

1. Material3 로컬 source와 현재 실사용 역할, 수치를 조사해 토큰을 정의한다.
2. 공통 테마와 화면의 스타일 값을 이전하고 대비 불변식 검사를 추가한다.
3. 실제 앱의 테마, 확대 글꼴, 잠금 전환을 확인해 근거와 미실행 범위를 기록한다.

## 남은 문제와 인계

외부 지도 타일은 기존 Liberty 스타일이다. 앱 다크 테마만으로 지도 타일까지 다크로 변했다고 기록하지 않는다.
색 대비 계산은 sRGB 수치 검사이며 실제 기기의 눈부심, 모든 접근성 적합성을 인증하지 않는다. 비활성 컨트롤은 일반 글자 대비 합격으로 포장하지 않는다.
실제 네트워크 오류, 저장소 장애를 새로 모두 주입한 것으로 기록하지 않으며 상태별 문구, 기존 테스트와 새 토큰 검증의 범위를 구분한다.
JDK 치명 오류는 ENV-09(P0)로 별도 추적한다. 공식 패치 archive의 무결성, 서명 준비만 마쳤으며 새 런타임 설치, JIT 우회 없는 검증은 미실행이다.
추가 Cold boot, 런처 복구 뒤 DB v2의 준비 값, 완료 세션 3개 전체/active 0을 다시 확인했다. 설정, 저장 데이터를 보존하고 이번 작업이 소유한 AVD, 브라우저, 포워딩을 정리했다.
Pleos 중앙 화면 검증은 [공식 ADB 안내](https://document.pleos.ai/en/docs/pleos-only/vehicle-app-developer-guide/adb-command-reference-guide)의 LAUNCHER 경로와 실제 창/이미지를 함께 사용한다. native 활성 패키지, Compose 조건만으로 전면을 추정하거나 추가 GNB 탭을 무작정 반복하지 않는다. task 정리가 필요하면 저장 상태와 현재 소유, 구성을 먼저 확인하며 다른 작업의 앱 창은 보존한다.
