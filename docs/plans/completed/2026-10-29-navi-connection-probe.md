# NaviHelper 초기 연결 기술 검증

- 상태: 완료
- 요구사항: 공모전 지도/내비 기술 확인, MAP-04의 연결 선행 검증 (비공개 작업 명세)

## 목표와 범위

NaviHelper의 실제 초기 연결과 release 뒤 새 인스턴스 재연결을 전용 Pleos에서 확인한다. SDK는 core:vehicle의 계측 의존성에만 두고 제품의 미연결 표시, 경로 요청과 화면은 바꾸지 않는다. 목적지/경유지와 권한 허용, 정보 조회, 내비 화면 전환은 실행하지 않는다. 코스 좌표와 MAP-01 리뷰가 끝나야 하는 MAP-04 전체와 별도 선행 검증으로 관리한다.

## 완료 조건

- [x] 공식 SDK의 초기 연결 callback을 실제로 관찰하고 해제한 뒤 새 객체 재연결을 확인한다.
- [x] 실패 callback과 시간 초과를 연결 성공이나 길안내 가능으로 바꾸지 않는다. 새 권한 요청/부여와 경로/정보 API 호출이 없고 기존 앱 데이터와 설정을 보존한다.
- [x] JDK17 전체 검사, 계측 APK, 실제 연결/정리 근거, 최신 PR CI와 Codex 리뷰를 확인한다.

## 구현 단계

1. 공식 문서, Maven 배포 SDK의 초기화와 release 구현, manifest와 의존성을 확인한다.
2. core:vehicle 계측에서만 실제 SDK 초기화와 재연결을 확인한다.
3. 무거운 빌드와 Pleos 계측을 순차 실행하고 실패/미실행/성공과 남은 경로 검증을 구분한다.

## 남은 문제와 인계

최초 연결만 확인했으며 경로 요청, 정보 조회, 내비 화면과 실제 경로 일치, 전후 안내 경로 readback은 미실행이다.
제품 NavigationGateway는 여전히 미연결 구현이며 이 결과를 지속 연결이나 길안내 가능으로 표시하지 않는다.
MAP-04 전체는 MAP-02의 코스 좌표와 실제 기능 권한/요청 결과 검증이 필요하다. MAP-01의 기존 최종 리뷰도 별도 추적한다.
코드 커밋의 최신 CI와 Codex 리뷰 확인 뒤 이 선행 검증 계획만 완료로 이동했다. 최종 문서 커밋도 CI와 리뷰를 확인한 뒤 병합하며 전체 MAP-04는 체크하지 않는다.
실행 방법과 해석 범위는 [내비 최초 연결 기술 확인](../../development/navi-connection.md)에 기록했다.
