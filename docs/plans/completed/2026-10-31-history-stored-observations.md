## README 사례 비교

현재4개는 fail-closed SDK 상태, 파괴적 저장의 CAS/트랜잭션, reader/renderer/native 입력 수명, SQLite 실제 자료형 경계를 설명한다. 새 열람 연결이 기존 어느 사례보다 원인 증거, 비동기/데이터 경계 판단과 재현 결과를 더 설득력 있게 입증하는지 최종 근거로 비교한다. 새로움/코드량/테스트 개수로 대체하지 않으며 근거가 없으면 내용과 순서를 보존한다. README에 회귀 수/목록이나 CI/JUnit 설명을 넣지 않는다.

## 남은 문제와 인계

실제 도로 구간, 위치 연속 수집, 내비 전환 수집과 지도 복습 및 전체 APP-06/APP-08은 이번 범위의 완료로 처리하지 않는다. 과거 최종 리뷰 미확인은 별도 관리하며 독립 구현을 막는 기술 의존성으로 대체하지 않는다. 원래 SDK 저장 기록이 없는 과거 행의 빈 결과를 0/정상 주행으로 바꾸지 않는다. 기존 AVD/자료/권한/설정은 보존한다.

## 구현 검토와 초기 검사 정정

- 기존 History receipt의 동일 lock/reader/query/generation/full source에 하위 cold observation reader를 연결했다. 별도 sessions reader를 만들지 않는 대안을 골라 두 선택 기준의 합의 지점을 줄였다. detail reader/query/revision token과 현재 행 ID를 동작에 고정하며 직접 읽은 거부가 부모/상세의 옛 세대를 폐기한다. 이 구현 검토 시점에는 cold 수집/원본 순서/터미널 실패와 명시 retry의 실제 검사가 후속이었다. 최종 결과는 아래에 따로 기록한다.
- 첫 품질 검사는 새 함수 파일의 PascalCase 이름 규칙으로 실패해 FrozenObservationClick.kt로 고쳤다. 재포맷/품질은 통과했다. 첫 JVM 실행의40개 새 검사 중1개는 stateIn 표시 전달 전에 Locked를 기대해 실패했다. 제품의 producer 소유권은 동기적으로 무효화되지만 UI 복사본 전달은 scheduler 뒤여서, 즉시 parent guard/old token/page 거부와 runCurrent 이후 parent/child Locked/구독0을 분리하고 P 복원 뒤 옛 세대 거부를 추가했다. 제품 구현을 약화하거나 성공 기본값으로 바꾸지 않았으며 최종 전체4단계와45suites654개 실패/오류/건너뜀0, debug/unsigned release 및 계측 APK로 재검증을 통과했다. 이 자동 검사 시점에는 앱 실기가 미실행이었다.
- 독립 코드 검토는 확정 제품 결함/거짓 양성을 찾지 못했다. 이는 실제 실행 통과와 별도 근거다. 접근성 callback이 새 clickable 콜백을 따라가지 않게 표시 당시 동작을 고정했다.
- README는 기존4개 사례를 보존한다. 새 읽기 경계는1번 live/source gate와3번 reader/query 수명을 확장하지만, 2번 파괴적 CAS/트랜잭션과4번 SQLite 물리 형식 오염보다 독립적인 원인 규명과 데이터 영향 근거가 강하지 않다. 이 최초 비교 시점에는 교체를 판단할 실제 전후 성능/사용 흐름 근거가 아직 없었다. 최종 실측과 사례 선정 판단은 아래에 기록한다. 현재 코드로 바뀐5개 anchor와 분리된 삭제 guard1발췌만 정합 갱신해17개 실제 연속 코드/기존18개 이미지/순서/브랜드를 보존했다. 당시에는 실제 화면 검증 전이어서 새 기능 소개를 추가하지 않았다. 이후 실제 화면을 검증한 뒤 기능 표 한 문장만 추가했다.
