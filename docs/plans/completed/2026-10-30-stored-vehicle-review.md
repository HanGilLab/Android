- 상태: 완료 (제품 구현/자동 검사/실기와 구현 커밋 리뷰, 최종 문서 검사는 PR에서 별도 추적)
- 요구사항: APP-06의 저장 관찰 열람 부분, APP-04의 검증된 전면 수집 계약 재사용
- 기준: 62d710beb7b768ee71dba3126bd62c745ff677f7

## 목표와 범위

앱에서 실제 저장한 최근 종료 세션의 차량 상태를 주차 후 확인한다. 최근 연습의 접힌 상세 안에서 한 번에 한 스냅샷을 표시하고 이전/다음으로 저장 ID 순서를 따른다. 기어, 방향지시등, 브레이크와 연결 상태를 크게 표시하며 앱 관찰 시각과 실제 SDK 출처를 시연 코스와 구분한다.

기존 domain 조회 계약과 주차/UX 허용 경계를 사용한다. 새 모듈, 위치/백그라운드 권한, DB 변경과 쓰기는 없다. 구간별 지도, 부담 구간, 메모와 APP-06 전체 완료는 이번 범위가 아니다. 과거 PR8/10의 원래 최종 리뷰와 MAP-01 전체는 별도 미완료로 유지하지만 이 기능이 해당 API를 호출하지 않으므로 독립 구현한다.

## 변경 전후 측정

이번 범위는 아직 없던 저장 기록 열람 기능의 추가다. 기준 main에는 동등한 열람 경로가 없어 같은 입력/동작의 실행 성능 전후 비교를 성립시킬 수 없다. 성능 병목을 관찰해 최적화하는 작업이 아니므로 개선율을 주장하지 않는다. 회귀 통과 수나 저장 행 수는 기능 정확성의 별도 근거이며 성능 수치를 대신하지 않는다. 추후 실제 병목을 관찰하면 측정 계약에 따라 코드 변경 전 기준값부터 측정한다.

- 병목과 관찰 근거, 개선 가설: SDK 관찰은 저장되지만 사용자 열람 기능이 없음. 성능 가설 없음.
- 지표와 단위, 비교 방향: 성능 비교 적용 제외. 열람/잠금/오류/순서 동작과 보존을 검증한다.
- 기준 커밋과 비교 커밋: 기준62d710b, 비교는 PR의 실제 head로 추적한다.
- 동일 입력/부하, 빌드 종류와 실행 조건: 기존 전용 Pleos debug 앱의 실제 저장 자료, 원래 행과 권한을 보존한다. 자동 fixture를 실제 SDK 성과로 계산하지 않는다.
- 워밍업, 반복/표본 수와 전후 실행 순서: 성능 표본 미수집. 일반 라이트와 확대 다크 실기는 별도 기능 검증이다.
- 원값 보존 위치와 재현 절차, 실패/제외 표본 기준: 개인별 자료/원본 화면/원문 로그는 ignored 비공개 기록, 정제한 검증만 계획과 PR에 기록한다.

## README 사례 선정과 비교

현재 4개는 주행 갱신 경쟁, 저장 중 잠금/중복 트랜잭션, 재생성 지도 callback, SQLite 물리 타입 무결성을 설명한다. 새 열람 기능은 기존 계약의 제품 적용이며 아직 더 강한 원인 규명이나 전후 실측 성능 근거가 없다. 새 근거를 확보한 뒤 채용 관점의 경계 난도/판단/재현성으로 비교하며, 근거 없이 사례 수를 늘리거나 순서를 바꾸지 않는다. README에는 회귀 검사 목록/개수/집계나 미측정 성과표를 넣지 않는다.

## 남은 문제와 인계

구현/자동 검사/최종 일반 및 확대 다크 실기는 통과했다. 구현252a603의 최신 CI4개와 동일 head Codex 리뷰는 통과했다. 최종 문서 정리 커밋의 검사/리뷰와 병합은 아직 확인 전이며 해당 PR의 실제 최신 상태로 별도 판정한다. APP-04의 위치, 내비 전환 지속 수집과 영속적 누락 구간, APP-06의 지도/메모, MAP-01의 원래 최종 리뷰와 전체 완료는 별도다. 기존 자료와 권한은 보존하고 소유한 자원만 정리한다.


비공개 helper의 최초 import 실행은 기준 파일 경로가 설정되지 않아 실제 앱 작업 전에 실패했다. 기준 경로를 지정한 뒤 기존 AVD에서 다시 실행했으며 제품 결함이나 실기 실패로 해석하지 않는다. 첫 일반 실기 통과와 최종 문구/촬영 판정 소스의 두 실기 통과를 분리해 보존했다. 회귀/실기 수는 정확성 근거이며 성능 수치가 아니다.

독립 문서 검토에서 관찰 시각을 DB 저장 완료 시각으로 오해할 수 있는 표현 1곳을 모델의 실제 관찰 시각으로 정정했다. 이미지의 잘림/민감정보/성과 과장과 펼침 판정에는 추가 구체 지적이 없었다.


## 구현 커밋의 CI와 리뷰

[PR #38](https://github.com/HanGilLab/Android/pull/38)의 구현252a603b22f859a44c7b69a177b616b5d0bedcd7에서 [필수 CI4개](https://github.com/HanGilLab/Android/actions/runs/41022182452)와 [동일 head Codex 완료/지적 없음](https://github.com/HanGilLab/Android/pull/38#issuecomment-6517646969)을 확인했다. 전체 스레드/정식 리뷰/미해결 지적0, nondraft/CLEAN을 확인했다. 이 계획을 완료 위치로 정리하는 후속 커밋은 제품/단위/계측/빌드 소스를 변경하지 않는다. 후속 커밋의 CI와 Codex 리뷰는 다시 확인하며 위 구현 커밋의 통과를 자동 승계하지 않는다. 실제 병합/끝 커밋/동일 트리와 main ff-only, 병합 브랜치 정리, main 후속 CI는 PR과 비공개 체크포인트 및 Notion에서 확인한다.
