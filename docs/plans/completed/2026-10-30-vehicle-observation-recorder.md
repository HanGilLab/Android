# 차량 관찰 기록 실행 경계

- 상태: 완료
- 요구사항: APP-04의 독립 선행 구현, 기존 차량 관찰 저장 계약

## 목표와 범위

기존 VehicleGateway 상태를 호출자가 지정한 단일 세션에 순차 저장하는 순수 Kotlin 실행기를 추가한다.
저장 기반의 후속 단계이며 제품 앱에 연결하거나 MAP-01/APP-04 전체를 완료 처리하지 않는다.
새 권한, SDK/DB/화면 변경과 백그라운드 서비스는 포함하지 않는다. 호출자가 세션 종료/화면 수명주기에 맞춰 실행을 취소해야 한다.

## 완료 조건

- [x] 관찰 상태와 주입한 앱 시각을 그대로 순차 전달하며 SDK 이벤트/발생 시각으로 추정하지 않는다.
- [x] 한 실행기 인스턴스에서 중복 실행을 거부하고 세션을 자동 전환하지 않는다.
- [x] 없는/종료 세션, 잘못된 시각과 저장 예외를 구분해 중단하며 취소와 원인을 보존한다.
- [x] 지연 저장 중 StateFlow의 중간 상태 생략을 숨기지 않고 취소 뒤 실행권을 해제한다.
- [x] 의미 있는 회귀 검사와 JDK17 전체 검사, 최신 PR CI/Codex 리뷰를 확인한다.

## 구현 단계

1. 기존 domain/저장/차량 계약, active 계획과 실제 리뷰 대기를 확인한다.
2. 고정 세션과 단일 실행의 기록 경계, 결과 타입과 결정적 비동기 검사를 구현한다.
3. 독립 검토와 JDK17 전체 검사 후 실제 제한을 문서화하고 PR 최신 검사를 추적한다.

## 남은 문제와 인계

제품 수집 수명주기, 실제 SDK→Room 연결, 내비 전환 중 유지, 누락 표시와 프로세스 종료 복구는 별도 구현/실기다.
StateFlow는 모든 SDK 콜백과 동일 값 반복을 보장하지 않는다. 저장 성공 수는 운전자 조작 횟수가 아니다.
종료/오류 뒤 재시작은 호출자의 명시적 새 실행이며 자동 재시도하지 않는다.
기존 PR #8/#10/#33의 running 리뷰와 필수19/54는 유지한다.

## README 사례 비교

새 실행기는 순차 저장/단일 실행/취소 경계의 역량을 보여 주지만 제품 앱과 실제 SDK→Room에는 연결하지 않은 선행 단계다.
기존1번은 실제 상세 조작에 적용한 최신 차량 상태 경합 차단, 2번은 실제 Room 트랜잭션의 동시 요청과 롤백 후 행 보존을 입증한다.
3번은 Native View 재생성과 늦은 callback의 실제 지도 경계, 4번은 SQLite 물리 자료형 오염과 기존 자료 마이그레이션 보존을 다룬다.
새 실행기의 제어된 상태/저장 응답만으로는 이 네 사례보다 실제 제품 영향과 재현 근거가 더 강하다고 판단하기 어렵다.
따라서 기존 네 사례의 내용과 순서, 근거 집계 대상을 보존한다. 테스트 총수와 단순 최신성은 교체 이유로 사용하지 않는다.
