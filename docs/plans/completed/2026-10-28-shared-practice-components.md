# 공통 연습 UI 컴포넌트와 상태 검증

- 상태: 완료 (코드 검증·CI·리뷰 완료, 완료 기록 커밋도 최신 검사 후 병합)
- 요구사항: [공모전 체크리스트 DES-05](https://app.notion.com/p/40586a7a8f8a800092c1caea490e8a09)

## 목표와 범위

기존 카드·배지·선택·잠금 컴포넌트를 유지하고 공통 버튼·로딩·빈 화면·오류 패널을 마련한다.
선택 항목의 비활성 상태도 명시해 클릭·선택 의미와 큰 터치 영역을 확인한다.
기존 디자인 토큰을 사용하며 독립적인 계측 화면에서 라이트/다크·기본/확대 글꼴 상태와 동작을 재현한다.
주입한 표시 상태를 실제 SDK 장애나 제품 복습 기능의 구현으로 계산하지 않는다.
전체 제품 화면 적용은 DES-06, 실제 지도 구간 선택은 MAP-03에서 진행한다.
실제 사용처는 코스 준비의 다음/돌아가기 버튼 2개만 공통 래퍼로 연결한다. 문구·enabled·콜백·저장 흐름은 유지한다.
독립 호스트는 debug 변형에만 존재하고 exported=false·런처 항목 없음·주행 최적화 예외 없음으로 선언한다.

## 구현 단계

1. 기존 디자인 시스템과 사용처를 확인하고 최소 공통 API를 추가한다.
2. 제품 로직과 분리한 계측 화면에서 각 상태와 콜백·비활성을 확인한다.
3. 무거운 Gradle 검사 후 기존 Pleos AVD에서 실제 표시를 검증하고 원래 상태를 복원한다.
4. 리뷰·CI·관련 검증 완료 후 노션 완료 조건과 PR 근거를 반영한다.

## 환경 재검증과 실패 기록

- 처음 Cold boot에서 앱 패키지의 설치·데이터 등록은 남았지만 등록 APK 경로가 없어 `run-as`가 패키지를 찾지 못했다.
  초기 백업은 오류 문구를 받아 실패했으며 원본 DB 손상으로 판단하지 않았다. 백업 도구는 패키지 준비와 SQLite 헤더·quick_check를 확인하도록 보완했다.
- 데이터를 지우지 않는 `install -r` 재설치 후 DB schema2·준비1건·연습3건 전체 행이 직전 검증과 같았다.
  같은 AVD의 다음 Cold boot에서는 재설치 없이 APK·원래 설정·DB 전체 행 유지가 확인됐다.
- 재부팅 직후 첫 SDK 계측은 프로세스 종료로 실패했다. 같은 시각 기본 내비의 시작·앱 작업 종료 로그와 실제 내비 전면을 별도 보존했다.
  이후 실제 SDK P/UX 해제·기존 준비 복원 계측이 통과했고 테스트 내부 native PNG에서 중앙 앱 표시를 확인했다.
  계측 종료 뒤 내비로 돌아온 캡처를 테스트 내부 앱 화면의 증거로 사용하지 않는다.
- 최초 계측 빌드의 불필요한 API import 오류1건은 수정 후 재빌드했다.
  카탈로그 첫2회는 native 제목 검색 조건에서 timeout으로 실패했다. 실행 중 native PNG/포커스에서는 실제 중앙 카탈로그가 보였다.
  캡처 조건을 Compose 제목 표시·native 활성 패키지·호스트 창 포커스로 보완했으며 실제 PNG 검토는 계속 필요하다.
  이후 글꼴 변경 직후 native 포커스 timeout1회와 새 Cold boot 직후 프로세스 종료1회도 별도 실패로 보존했다.
  최종 UI8개는 설정 변경 후 정상 앱의 native 포커스가 안정된 다음 실행한 결과다. 초기 계측 실패5개를 최종 성공에 포함하지 않았다.
- 권한 검사 도구의 JSON list/tuple 표현 차이로 보호 검사가1회 실패했지만 실제 전후 권한 집합은 같았다. 표현을 통일했으며 실제 권한 차이로 기록하지 않는다.

APK 소실의 근본 원인은 미확정이다. Pleos의 알려진 결함·메모리 부족·앱 코드 결함으로 단정하지 않는다.
후속 실행은 Cold boot용 `-no-snapshot-load`를 유지하고 snapshot 저장을 막는 옵션을 추가하지 않는다.
종료 전 guest 쓰기를 sync하고 이번에 시작한 에뮬레이터의 실제 종료를 확인하며, 기존 userdata·다른 장치·미커밋 변경을 보존한다.
[Pleos 설정](https://document.pleos.ai/docs/connect/guide/getting-started/application-development/setup-connect-sdk-emulator)과
[Android emulator 옵션](https://developer.android.com/studio/run/emulator-commandline)을 기준으로 하며 Quick boot로 VHAL 검증을 대체하지 않는다.

## 남은 문제와 인계

컴포넌트는 표시와 콜백만 제공한다. 상세 조작 허용은 호출 화면/도메인이 주차와 UX 해제를 모두 확인해야 한다.
미지원·미확인·단절·권한 거부를 정상/빈 결과로 바꾸지 않는다.
오류 패널의 행동은 호출자가 실제 가능한 동작만 제공한다.
위치 권한 동의·실제 SDK 입력 검증, 독립 UX 제어 경로와 대기 중 PR의 리뷰를 별도 미완료로 유지한다.

최종 실기8개와 별도로 실제 SDK P/UX 해제 프로브3회가 통과했다. 초기 계측 실패5회와 비교 도구의 보호 검사 실패는 별도 보존했다.
Native PNG56개는 독립 시각 검토를 포함해 모두 확인했고 구체적인 잘림·가림·선택·행동 중복 결함을 발견하지 못했다.
최종 원래 설정의 실제 SDK/홈과 전체 DB·권한 readback을 다시 확인한 뒤 소유 AVD를 sync·종료하고 종료를 관찰했다.
