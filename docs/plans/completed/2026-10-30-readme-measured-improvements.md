# Glim 형식의 README와 전후 측정 기반 개선

- 상태: 완료
- 요구사항: README를 Glim처럼 구성하고 문제 해결 4개와 실제 성능 전후 측정을 구분하라는 사용자 지시

## 목표와 범위

Glim의 실제 목차, 개요, 화면 갤러리, 기술 스택, 아키텍처와 담당 소개 구성을 한길에 맞게 적용한다.
문제 해결은 정확히 4개와 지정 순서를 유지하고 정확성 검증 수를 성능 성과로 전환하지 않는다.
AGENTS, 계획 템플릿과 기존 자동화2에 개선 전 기준 측정, 같은 조건의 전후 비교와 원값/분포/한계 기록을 저장한다.
앱 동작과 의존성, DB와 권한은 바꾸지 않는다. 별도 포트폴리오와 이력서는 열람하거나 수정하지 않는다.

## 남은 문제와 인계

현재 네 사례는 정확성과 데이터 보존 근거이며 실제 성능 전후 원값은 없다.
이번 README/문서 변경은 앱 실행 성능 변경이 없어 성능 측정 적용 대상이 아니며 성능 개선율을 만들지 않는다.
차기 실제 개선은 기준 측정부터 수행해야 한다. 계획 정리만 담은 최신 커밋도 필수 CI와 실제 Codex 리뷰를 확인한 뒤에만 병합한다.
최신 사용자 기준은 기존 자동화2와 노션 운영 문단에 저장했고 현재 채팅/2시간/기존 종료일을 보존했다.

## 참고 형식과 사례 선정

[Glim README](https://github.com/ois0886/Glim/blob/master/README.md)의 실제 목차/개요/화면 표/스택/아키텍처/팀 소개를 읽었다.
Glim에 배너/배지/문제 해결 영역이 있다고 주장하지 않으며 다른 프로젝트의 성과를 한길로 옮기지 않는다.
기존 네 사례를 대체할 실제 전후 성능 측정과 더 강한 제품 영향 근거가 없어 사례 내용과 순서는 보존한다.
테스트 수는 보조 회귀 근거로 두고 성능 개선 수치의 대체물로 사용하지 않는다.

로컬 미리보기 최초 도구 준비/빈 앵커 선택 시도는 실패했고 설치된 Chrome 재사용과 실제 제목 선택 후 렌더를 통과했다. 앱 결함이나 성능 결과로 계산하지 않는다.
