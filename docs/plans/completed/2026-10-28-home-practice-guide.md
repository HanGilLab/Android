# 첫 실행과 재실행의 홈 다음 행동 안내

- 상태: 완료
- 요구사항: 공모전 체크리스트 APP-01 (비공개 작업 명세)

## 목표와 범위

주차와 UX가 확인된 홈에서 준비→주행→주차 후 복습→다음 연습의 흐름과 현재 가능한 다음 행동을 보여준다.
첫 준비, 준비 완료, 진행 중, 종료 기록, 로딩, 오류를 구분하고 기존 준비/시작/마무리 동작으로 연결한다.
활성 연습의 목표, 코스, 과제는 현재 준비와 구분해 세션 스냅샷을 사용한다.
별도 온보딩 저장 플래그, DB 변경 없이 저장된 실제 상태로 안내를 복원한다.
복습, 메모, 다음 과제 연결은 미구현으로 표시하며 가짜 기능, 위치/차량 수집, 능력 평가를 추가하지 않는다.

## 완료 조건

- [x] 준비 없음/변경됨/완료, 활성, 종료, 로딩/오류의 다음 행동을 구분한다.
- [x] 차량/주차/UX 미확인과 제한 시 안내, 상세 행동을 숨기고 기존 저장 검증을 유지한다.
- [x] 활성 세션이 현재 준비와 달라도 연습 당시 목표, 코스, 과제를 안내한다.
- [x] 첫 상태와 재실행의 안내, 실제 행동, 대비/터치 영역을 화면에서 확인한다.
- [x] 기존 준비, 종료 세션을 보존하고 전체 검사, 관련 실기를 통과한다.
- [x] 최신 PR CI와 Codex 리뷰를 통과하고 미해결 지적이 없다.

## 구현 단계

1. 현재 상태와 선행 DES-04 토큰을 사용해 작은 안내 모델, 화면을 추가한다.
2. 기존 ViewModel의 주차와 UX 및 Repository 저장 검증 경로를 재사용한다.
3. 상태 전이, 안내/잠금 계측과 실제 Pleos 첫 상태/재실행을 검증한다.
4. 결과, 실패, 미실행을 구분하고 노션, PR에 실제 근거를 기록한다.

## 남은 문제와 인계

ENV-06 독립 UX/오류 주입, PR10 위치 동의 및 실제 SDK 수신, PR14 리뷰 대기는 별도 작업으로 유지한다.
이번 안내를 복습, 추천, 위치/차량 기록의 구현 완료로 표시하지 않는다.
활성 스냅샷과 변경된 준비가 다른 경우는 상태 단위 검사와 화면 코드 검토로 확인했으며 해당 조합의 별도 실제 입력은 실행하지 않았다.
검증 범위와 실행 전제는 [개발 안내](../../development/home-practice-guide.md)에 기록했다.
