# 전면 앱에서 활성 세션의 실제 차량 상태 기록 연결

- 상태: 완료 (최종 문서 커밋 검사는 PR에서 별도 추적)
- 요구사항: APP-04의 차량 관찰 부분, 사용자 작업 재개 지시

## 목표와 범위

이미 병합된 VehicleGateway, VehicleObservationRecorder와 Room 저장 계약을 제품에 연결한다.
앱 Activity가 STARTED이고 저장된 활성 세션이 있는 동안 실제 전달된 차량 상태를 해당 세션에 기록한다.
위치 조회, 지도, 내비 전환 후 백그라운드 유지, 실제 주행 경로와 복습은 이번 범위가 아니다.
과거 PR의 원래 head 리뷰 미완료는 전체 체크리스트의 완료 판정에 유지한다.
이미 검증된 현재 차량 어댑터와 저장 기반을 사용하는 독립 구현의 착수까지 차단하지 않는다.
원래 리뷰를 승인으로 바꾸거나 MAP-01, APP-04 전체를 완료 처리하지 않는다.

- [x] 재생성, 전면 복귀, 활성 세션 복원에서 단일 기록기를 유지하고 이전 세션과 종료 뒤 기록을 방지한다.

## 구현 단계

1. 기존 실행기와 저장 트랜잭션, Activity/홈 수명 경계를 확인한다.
2. 독립 수집 ViewModel과 Activity STARTED 연결, 상태 안내를 추가한다.
3. 취소, 세션 전환, 실패와 재시도 검사를 실행하고 JDK17 전체 검사 후 Pleos를 순차 검증한다.
4. README 네 사례와 새 근거를 비교하고 필요한 기능 설명만 갱신한다. 리뷰와 실제 병합 상태를 기록한다.

## 변경 전후 측정

이번은 미연결 수집 기능의 제품 연결이며 기존 성능 병목을 최적화하는 작업이 아니다.
기준 main 58234d5에는 실제 앱 SDK→Room 실행 경로가 없어 동등한 전후 성능 비교 대상을 만들 수 없다.
따라서 앱 성능 향상이나 개선율을 주장하지 않고 수집 동작, 취소 경계와 저장 원형을 검증한다.
저장 행/회귀 테스트 수를 성능 수치로 사용하지 않는다. 이후 관찰한 병목은 코드 변경 전에 별도 기준 측정부터 한다.

## README 사례 선정

기존 네 사례와 순서를 보존한다. 새 제품 연결에 더 강한 원인 분석, 대안과 실제 결과가 확보되면 그때 비교한다.
현재는 새로운 성능 성과나 다섯 번째 사례를 만들지 않는다.

## 남은 문제와 인계

APP-04 전체의 위치와 누락 표시, APP-05의 내비/백그라운드 수집은 후속이다.
StateFlow가 동일하거나 중간 상태를 생략할 수 있고 앱 관찰 시각은 SDK 이벤트 발생 시각이 아니다.
실제 ENV-06 독립 UX/오류 주입과 원래 PR8/10 리뷰 상태는 별도로 추적한다.

## 구현 중 독립 검토

- 수집은 주행 잠금으로 제거되는 홈 Composition에서 분리하고 Activity STARTED가 소유한다.
- 저장 작업 자체가 독립 CancellationException을 던지면 collectLatest 자식만 끝나 관찰 중 표시가 남을 수 있는 경로를 발견했다. 정상 수명 취소와 내부 작업 취소를 구분하는 회귀와 상태 정정을 추가한다.
- 활성 세션을 한 번 전달한 뒤 세션 Flow가 정상 종료하면 collectLatest가 무기한 기록 자식을 기다릴 수 있다. upstream 종료를 실패로 전환해 자식 취소와 오류 표시를 검증한다.
- 첫 전체 검사는 계측 소스 작성과 포맷 순서가 겹쳐 Spotless에서 실패했다. 앱 결함이나 성공으로 바꾸지 않고 모든 소스 확정 후 포맷/전체 검사를 순차 재실행한다.

- 수정 전 회귀 재현: SessionRecordingViewModelTest의 기존16개는 통과했지만 독립 저장 취소/저장 내부 timeout/시계 취소/세션 읽기 취소/활성 Flow 정상 종료를 추가한 focused 실행은 21개 중 해당5개 실패, 오류/건너뜀0으로 결함을 재현했다. 단순 테스트 수나 실행 시간은 성능 성과가 아니다.

- 수정 후 focused21개와 전체177개는 통과, 실패/오류/건너뜀0이며 품질, debug/unsigned release와 계측 APK도 통과했다. cache/up-to-date 포함이다.
- 첫 실기는 P/D 저장, 주행 잠금, CREATED 중 저장 중단, 복귀/재생성, 종료 후 실제 SDK 변화에서 행 불변과 기존 자료 보존까지 통과했지만 마지막 최근 기록 날짜 태그 대기에서 20초 시간 초과로 전체 실패했다. 원인은 아직 미확정이며 lazy 화면 탓으로 단정하지 않는다. 동일 판정을 유지한 채 태그 수/화면 상태 진단과 실패 시 비공개 캡처를 보강해 재검증한다.
- 첫 실기의 새 종료 세션1개를 보존하고 기존 준비, 종료 세션과 모든 관찰 행, 권한/현재 사용자 runtime 플래그/글꼴/야간 설정의 동일성을 확인했다. 보조 스냅샷의 tuple/list 비교 실패는 JSON 정규화 후 실제 동일함을 확인한 것으로 구분한다. 전면 기본 내비와 응답 지연은 실제 앱 패키지와 화면 확인 전 성공/앱 결함으로 해석하지 않았다.

- 첫 화면 확인 실패 원인 확인: 실시간 전체 화면에서 방향지시등으로 생성된 Pleos 측면 카메라가 앱 위에 떠 있는 것을 확인했다. 최근 종료 날짜는 실제 앱에 표시됐지만 플랫폼 카메라가 접근성 루트를 가렸다. 신호를 원래 값으로 복원한 뒤 동일한 날짜 태그 판정과 최종 캡처를 유지한 2차 실기1개가 통과했고 건너뜀0이다. 앱/lazy 문제로 선언하거나 검사를 약화하지 않았다. 최종 계측에는 명시적 신호 복원 phase와 실제 SDK 복원/종료 행 불변 재확인을 추가한다. 기존 자료/권한/설정 보존을 확인하고 소유 AVD만 종료했다.

## 최종 실기와 자료 보존

- 최종 계측은 실제 P/D를 같은 활성 세션에 저장하고 주행 잠금을 확인했다. Activity CREATED 중 실제 SDK 변화에도 저장은 늘지 않았고 복귀/재생성에서 같은 세션 기록을 재개했다. 종료 뒤 새로운 SDK 신호와 원래 신호 복원 모두에서 행이 추가되지 않았다.
- 일반 라이트와 확대1.3/다크 화면의 상태 문구, 실제 버튼 도달, 복귀와 최근 종료 기록을 캡처로 직접 확인했다. 마지막 날짜 라벨 검사는 그대로 유지했으며 플랫폼 카메라 해제 이후에 실제 앱 전면을 확인했다.
- 초기 실패가 만든 종료 세션도 보존했다. 기존 전체 준비/세션/관찰 행과 권한/현재 사용자 runtime 플래그, 글꼴/야간 설정은 원래 값과 동일하다. 검사 자료만 새 종료 세션으로 추가됐고 기존 데이터 삭제/덮어쓰기나 새 권한 부여는 없다. 소유 AVD와 포워딩, 임시 콘솔을 종료했다.
- README 기능 소개와 일반 화면은 현재 UI로 갱신하고 실제 SDK 관찰 안내/주행 잠금 캡처를 추가했다. 앱 영역의 원본 픽셀만 잘라 사용하고 메타데이터를 제거했다. OS/콘솔/카메라 화면과 실제 위치를 공개 이미지에 넣지 않았다.

## 네 사례 유지 판단

새 연결의 핵심은 이미 검증된 실행기와 저장 계약의 제품 적용이다. 독립 취소와 Flow 완료 결함은 재현/수정했지만 기존1의 실시간 상세 조작 경계,2의 저장 트랜잭션,3의 Native View 재생성/지연 콜백,4의 SQLite 타입 손상 경계보다 더 강한 사용자 영향이나 전후 실측 성능 근거를 확보한 사례는 아니다.
기존 네 사례가 서로 다른 기술 경계를 보여 주므로 선정과 순서, 핵심 코드/소스 링크를 보존했다. 4번 사례의 수집 연결이 아직 없다는 오래된 범위 문장만 현재 전면 연결 완료와 후속 내비/복습 구분으로 정정했다. 새로운 성능 개선율, 다섯 번째 사례나 회귀 근거를 README에 추가하지 않는다.
