- 요구사항: 원본 저장소와 기존 PR을 유지하며 비공개 기획 주소와 개인별 민감한 환경 정보의 노출을 정리한다.

## 목표와 범위

현재 추적 파일의 비공개 작업 주소를 제거하고 로컬 DB, 서명, 진단 기록의 실수 커밋을 막는다.
일반 공개 SDK 의존성과 재현 안내를 사용자별 설치 위치, 기기, 권한, 원문 검증 기록과 구분한다.
사용자 최종 지시에 따라 원본 저장소의 이름, ID와 PR을 유지하며 일반 main 이력의 비공개 기획 주소를 정리했다.
본인의 작성자 이메일은 사용자가 공개를 허용했으므로 제거 대상이나 차단 사유로 취급하지 않는다.

- [x] 로컬 데이터, 서명 파일의 추적을 방지하고 제한된 공개 콘텐츠 검사를 추가한다.

## 구현 단계

1. 현재 파일의 비공개 주소를 제거하고 추적 파일 패턴 검사, 로컬 데이터 ignore 규칙을 추가했다.
2. 사용자 범위 변경을 반영해 별도 저장소 분리와 교체 방식을 취소하고 임시 준비물을 정리했다.
3. 비공개 백업을 보존한 뒤 승인된 범위에서 원본 main 이력을 정리하고 보호 규칙을 복구했다.
4. 실제 공개 접근, CI와 로컬 검증을 확인했다. 기존 PR의 원래 head와 리뷰 기록은 유지한다.

## 남은 문제와 인계

최신 파일과 일반 main 이력의 정리는 GitHub의 기존 PR 참조와 캐시 제거를 의미하지 않는다.
서버 잔여 참조까지 제거됐다고 주장하지 않으며, 지원 메시지나 같은 승인 질문을 반복하지 않는다.
실제 자격정보와 개인키는 수행한 검사에서 발견되지 않았으나 제한된 패턴 검사만으로 모든 비밀의 부재를 보장하지 않는다.

분리 공개 전략, 별도 저장소 생성, 원본 이름 변경, PR 숨김과 추가 이력 재작성은 진행하지 않는다.
정리 전 clone이나 브랜치의 이력을 현재 main에 merge하거나 mirror-push하지 않는다.
늦은 PR 리뷰 지적은 현재 main에서 새 `codex/` 브랜치와 PR로 수정하며 원래 리뷰 식별자를 보존한다.
PR #8과 #10의 최종 Codex 리뷰는 계속 진행 중이므로 이 계획의 완료와 별도로 추적한다.

3시간 간격의 새 채팅 자동화는 재개됐으며 2026-11-10 한국 시간 종료를 유지한다.
완료 근거의 정합 확인이므로 새로운 공개 전환, 규칙 완화, 이력 정리를 수행한 것으로 기록하지 않는다.
