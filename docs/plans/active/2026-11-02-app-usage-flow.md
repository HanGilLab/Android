## 변경 전후 측정

문서가 설명하는 사용 흐름을 바꾸는 제품 구현이 아니라 현재 코드를 도식으로 설명하는 변경이다. 제품/native/APK/SDK와 측정 입력을 변경하지 않으므로 앱 성능 전후 계측 적용 제외다. 이번 문서 대조, 렌더와 검사 시간/개수를 앱 성능이나 실제 UI 성공으로 만들지 않는다. 새 실제 화면/권한/위치 관찰/저장/JDI/AVD 실행을 하지 않는다.

## README 사례 비교와 남은 문제

새 근거는 제품을 변경해 해결한 사례가 아니라 기존 사용자 행동을 설명한 도식이다. 기존 네 사례가 입증하는 원본 소유권, DB 원자 삭제, 비동기 지도 입력과 재진입 상태 경계보다 강한 새 제품 해결을 입증하지 못하므로 교체하지 않는다. 정확4개/지정6항목/실제 펼침 코드/기존 브랜드와 화면을 그대로 보존한다.

이 도식으로 기존 APP/MAP/QA/디자인 전체를 완료로 체크하지 않는다. PR74/75 관련 실제 수동 검증, 독립 UX 제어 제약, 실제 도로 복습/내비 경로/사용자 참가 정보와 서명/발송은 각각 미완료로 유지한다.


## 문서 검증과 실제 실행의 구분

현재 main의 NavHost와 실제 Route/버튼/문구/VM을 대조했다. 최근 메모와 지난 연습의 기존 메모 수정 조건을 구분했고, debug 권한 허용 시 같은 요청/현재 조건이 유효하면 즉시 마지막 위치를1회 조회하는 실제 흐름을 반영했다. 준비 저장과 다음 준비 저장은 연습 자동 시작이 아니라 홈의 새 명시 선택으로 표시했다.

Mermaid11.12.1과 격리 headless 브라우저로 최종10개 도식의 문법과 라이트/다크20개 렌더를 확인했다. 첫 넓은 도식을 실제 렌더에서 확인한 뒤 최근 복습, 다음 준비와 이력 열람으로 나누고 문구를 정리했다. 실제 PNG를 열어 주요 분기/한글/조건 문구를 확인했으며 새 앱 화면이나 AVD 검증으로 계산하지 않는다. 소스 상대 링크18개가 모두 현재 존재한다. 공개 개인정보/개인 경로/비공개 주소와 가운데점이 없음을 별도로 확인한다.

JDK17.0.21의 전체 ./scripts/verify.sh가 exit0, 네 BUILD SUCCESSFUL과 BUILD FAILED0으로 완료됐다. 캐시/UP-TO-DATE를 포함한 회귀/빌드 결과이며 성능 측정이나 신규 앱 실기 성공이 아니다. 공식 안내/공지/접수양식8개는 이번 공개 GET이 모두200이고 이전 기준 원바이트/hash와 동일했다. 제출/서명/외부 발송, 권한/위치/JDI/AVD 실행은0이다. README의 원바이트와 정확4개/여섯 항목 순서를 보존한다. 최신 PR의 CI/Codex와 실제 병합/정리는 계속 별도로 추적한다.
