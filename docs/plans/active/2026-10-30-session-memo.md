- 상태: 진행 중
- 요구사항: APP-06의 사용자 메모 저장/복원 부분. 기존 저장 관찰과 별도 출처로 관리한다.
- 기준: 874e330ad129f36fa4560810c31f2cf9d7ca9c6c

## 목표와 범위

최근 종료 세션에 주차 후 짧은 사용자 메모 하나를 남기고 저장/수정/명시적 지우기 및 재실행 복원을 제공한다. SDK 기록을 메모나 운전 평가로 바꾸지 않는다. 기존 세션/관찰 행은 변경하지 않으며 메모는 별도 domain 계약/Room 테이블로 둔다. 위치/지도/내비 API나 새 권한/모듈은 필요하지 않으므로 과거 리뷰와 전체 선행 항목 미체크와 분리해 구현한다. 지도 구간별 복습과 APP-06 전체는 완료 처리하지 않는다.

## 변경 전후 측정

새 메모 저장/열람 경로를 추가하는 기능이며 기준 main에는 동등한 동작이 없다. 성능 병목을 관찰한 최적화가 아니므로 전후 개선율을 주장하지 않는다. 회귀 개수/보존 행/롤백 결과는 정확성 근거이며 성능 수치가 아니다. 추후 실제 병목을 관찰하면 측정 계약대로 코드 변경 전에 기준값부터 측정한다.

- 병목과 관찰 근거, 개선 가설: 사용자 메모 기능이 없음. 성능 가설 없음.
- 지표와 단위, 비교 방향: 성능 비교 적용 제외. 저장/복원/충돌/잠금/보존/키보드 도달을 확인한다.
- 기준 커밋과 비교 커밋: 기준874e330, 비교는 PR 실제 head로 추적한다.
- 동일 입력/부하, 빌드 종류와 실행 조건: 기존 전용 Pleos debug 앱, 실제 v3 복사본 선행 검사와 격리 자료, 테스트 소유 세션의 일반적인 메모만 사용한다.
- 워밍업, 반복/표본 수와 전후 실행 순서: 성능 표본 미수집. 자동 검사와 실제 기본/확대/다크는 기능 검증이다.
- 원값 보존 위치와 재현 절차, 실패/제외 표본 기준: 원문 DB/메모/기기/환경/화면/로그는 ignored 비공개 기록. 실패/미실행/미지원과 성공을 분리한다.

## 검토에서 수정한 구체 결함

- 삭제 확인이 열려 있는 동안 다른 저장본이 들어오면 현재 토큰으로 삭제할 수 있던 경로를 발견했다. UI에서 표시했던 버전을 고정하고 VM이 현재 원본/편집 버전과 대조하며 DB에도 그 토큰만 전달하도록 바꿨다. 원래 결함을 단위 테스트에서 재현한 뒤 수정 후 같은 검사가 통과했다.
- 충돌 후 수정 취소가 새 조회 없이 `needsReload`를 해제하던 경로를 발견했다. 취소로 우회하지 못하게 하고 명시적으로 초안을 버리고 다시 읽는 동작만 허용한다. 초안과 이전 토큰은 충돌 동안 보존한다.
- 독립 소스 재검토에서는 이 수정 뒤 추가 구체 결함을 찾지 못했다. 실제 Pleos/네이티브와 PR 리뷰를 대신한 승인으로 쓰지 않는다.

## README 사례 선정과 비교

기존 4개와 코드/순서를 보존한다. 메모의 트랜잭션/버전/초안 경계는 새 실제 근거를 확보한 뒤 기존 사례의 기술 난도/원인 규명/대안/재현성보다 채용 관점에서 더 강한지 비교한다. 숫자/최신성만으로 교체하지 않고 성능 미측정 결과를 성능 개선으로 표현하지 않는다. README에 회귀 목록/집계를 넣지 않는다.

## 남은 문제와 인계

구현/자동 검사/실기/최신 리뷰는 미완료다. 실제 차량 키보드가 새 선행 조건이며 지원을 추정하지 않는다. 실제 v3→v4 보존 검사 전에 제품 DB를 임의 변환하거나 원래 자료/메모를 시험 문구로 덮어쓰지 않는다. 전체 APP-06/APP-04/MAP-01과 과거 원래 head 리뷰는 별도 미완료로 유지한다.
