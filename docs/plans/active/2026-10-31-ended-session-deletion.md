## 목표와 범위

이력에서 사용자가 고른 종료 세션을 명시 확인 후 기기에서 삭제하고 해당 차량 관찰/사용자 메모도 함께 정리한다. 현재 PracticeSessionRepository/DAO와 이력 화면에는 삭제 경로가 없어 기록을 기기 내에서 지울 수 없다. schema4는 이미 부모 세션에 연결 관찰/메모의 FK CASCADE를 갖고 있다. 이는 데이터 관리 기능의 공백이며 느리다는 추측으로 최적화하는 작업이 아니다.

선택한 종료 PracticeSession 전체 스냅샷과 당시 관찰 수/메모 version(없음 null 포함)을 확인 대상으로 고정한다. 독립 SessionDeletionRepository가 prepare와 delete를 나누고 실제 트랜잭션에서 대상/종료/연결 자료를 재확인한다. 삭제 전후 live P+UX/현재 reader/query/source/확인 nonce/화면 STARTED와 취소를 검사해 마지막 commit 전 거부면 CASCADE까지 rollback한다. Missing/Active/Changed/Blocked/Deleted/실제 저장소 오류를 구분하며 이미 없음은 성공이 아니다. commit 뒤 이탈을 소급 rollback한다고 보장하지 않는다.

확인창은 복구 불가/연결된 관찰과 메모/이 기기 삭제 범위를 짧고 분명하게 보여 주고 기본/확대/다크에서 실제 동작을 확인한다. STOP/닫기/선택 또는 조회 변경/잠금 뒤 옛 확인을 재사용하지 않고 새 명시 확인을 요구한다. 성공 후 다른 기록을 자동 선택하지 않는다. 활성 세션과 준비, 다른 세션 자료는 삭제하지 않는다. 과정 완료 판정, 지도 구간 복습, 위치/내비 지속 수집은 범위 밖이며 기존 P0 독립 UX 이미지 차단이나 PR8/10 미확인 리뷰를 전체 후속 구현의 대기 조건으로 쓰지 않는다.

## 구현 단계

1. 계약과 실제 기술 의존성을 확인하고 고정 계측/격리 지원만 먼저 준비한다. 아직 제품 삭제를 구현하지 않은 기준 이력 진입을 측정한다.
2. 작은 삭제 계약/실제 Room transaction과 이력 확인 수명 경계를 구현한다.
3. 별도 소유 DB의 실제 자료/삭제/rollback/충돌/다른 행과 sequence 보존, 원래 DB 전후 읽기 동일성을 확인한다. 원래 사용자 기록을 대상으로 삭제 실험하지 않는다.
4. 같은 계측 비교와 실제 화면/전체 검사/PR/CI/리뷰를 수행하고 결과를 과장하지 않고 기록한다.

## README 사례 선정과 문서 검증

기존2번은 중복 시작의 유일 인덱스와 쓰기 전후 트랜잭션이 중심이었다. 새2번은 실제로 없던 종료 기록 삭제를 연결하면서 사용자가 확인한 전체 snapshot/메모 없음 또는 version을 파괴적 쓰기 시점에 재비교하고, 명시 nonce/화면 STARTED/reader/query/source/Job과 실제 Room rollback을 연결한다. 자기 삭제 관찰이 typed Deleted보다 먼저 도착하는 순서도 다뤄 데이터 손실을 막는 판단과 비동기/데이터 경계의 구현 기여가 더 구체적이다. 실제 격리 Route/SQLite와 별도 실제 SDK 확인/취소/P-D-P, 같은 메서드의 전후 비용 관찰을 확보했으므로2번만 즉시 교체한다. 테스트 총수나 최신성으로 우월하다고 판단하지 않는다.

1번은 접근 잠금,3번은 native 지도 입력,4번은 관찰 raw 변환이 중심이어서 교체할 더 강한 근거가 없다. 해당 서술/순서는 보존했다. 현재 유효한 소스를 유지하기 위한1번 VM line anchor,4번 DAO 실제 count3줄/range만 최소 갱신했으며 새로운 사례 교체로 세지 않는다. 브랜드/목차/개요/기존 이미지/스택/모듈/담당 소개를 보존하고 기능표에 실제 삭제 동작만 한 행 추가했다. 정확4사례, 각6항목 순서와 실제 펼침 발췌를 유지하며 회귀 검증 집계는 README 밖에 둔다. 집계 도구의2번 대상을 RoomSessionDeletionRepositoryTest와 SessionHistoryDeletionViewModelTest로 맞췄다.
