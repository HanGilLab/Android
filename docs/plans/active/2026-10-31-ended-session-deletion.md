# 선택한 종료 연습 기록과 연결 자료 삭제

- 상태: 진행 중
- 요구사항: 출품 체크리스트 APP-08, QA-01/02의 기기 내 기록 삭제
- 기준 제품:3903bc624dbd7be0f0a39f31bc7f7b490703f218

## 목표와 범위

이력에서 사용자가 고른 종료 세션을 명시 확인 후 기기에서 삭제하고 해당 차량 관찰/사용자 메모도 함께 정리한다. 현재 PracticeSessionRepository/DAO와 이력 화면에는 삭제 경로가 없어 기록을 기기 내에서 지울 수 없다. schema4는 이미 부모 세션에 연결 관찰/메모의 FK CASCADE를 갖고 있다. 이는 데이터 관리 기능의 공백이며 느리다는 추측으로 최적화하는 작업이 아니다.

선택한 종료 PracticeSession 전체 스냅샷과 당시 관찰 수/메모 version(없음 null 포함)을 확인 대상으로 고정한다. 독립 SessionDeletionRepository가 prepare와 delete를 나누고 실제 트랜잭션에서 대상/종료/연결 자료를 재확인한다. 삭제 전후 live P+UX/현재 reader/query/source/확인 nonce/화면 STARTED와 취소를 검사해 마지막 commit 전 거부면 CASCADE까지 rollback한다. Missing/Active/Changed/Blocked/Deleted/실제 저장소 오류를 구분하며 이미 없음은 성공이 아니다. commit 뒤 이탈을 소급 rollback한다고 보장하지 않는다.

확인창은 복구 불가/연결된 관찰과 메모/이 기기 삭제 범위를 짧고 분명하게 보여 주고 기본/확대/다크에서 실제 동작을 확인한다. STOP/닫기/선택 또는 조회 변경/잠금 뒤 옛 확인을 재사용하지 않고 새 명시 확인을 요구한다. 성공 후 다른 기록을 자동 선택하지 않는다. 활성 세션과 준비, 다른 세션 자료는 삭제하지 않는다. 과정 완료 판정, 지도 구간 복습, 위치/내비 지속 수집은 범위 밖이며 기존 P0 독립 UX 이미지 차단이나 PR8/10 미확인 리뷰를 전체 후속 구현의 대기 조건으로 쓰지 않는다.

## 완료 조건

- [ ] 제품 삭제 코드 전에 측정 계획/고정 계측과 기준 이력 진입 원값을 실제 실행한다.
- [ ] 선택한 종료 source/확인 target/연결 자료 version을 트랜잭션에서 재확인하고 삭제/실패/잠금/취소를 구분한다. 스키마와 다른 자료를 보존한다.
- [ ] 이력의 명시 삭제 확인과 최신 P+UX/source/STARTED/nonce를 연결하고 중복/늦은 확인과 잘못된 재활성화를 차단한다.
- [ ] 실제 Room/SQLite와 실제 Route의 검사 소유 별도 DB에서만 삭제를 실행한다. 원래 DB에는 검사 세션을 만들거나 삭제하지 않고 sequence를 낮추지 않는다.
- [ ] 관련 단위/격리 native/실제 SDK P-D-P/기본/확대 다크와 전체 JDK17 verify, 동일 비교 계측, 원본/권한/설정 보존을 확인한다.
- [ ] 최신 PR 필수 CI/Codex/정책/미해결 지적0 뒤 정상 병합/main ff-only/해당 브랜치 정리, Notion/README4사례 비교와 계획 마감을 수행한다.

## 구현 단계

1. 계약과 실제 기술 의존성을 확인하고 고정 계측/격리 지원만 먼저 준비한다. 아직 제품 삭제를 구현하지 않은 기준 이력 진입을 측정한다.
2. 작은 삭제 계약/실제 Room transaction과 이력 확인 수명 경계를 구현한다.
3. 별도 소유 DB의 실제 자료/삭제/rollback/충돌/다른 행과 sequence 보존, 원래 DB 전후 읽기 동일성을 확인한다. 원래 사용자 기록을 대상으로 삭제 실험하지 않는다.
4. 같은 계측 비교와 실제 화면/전체 검사/PR/CI/리뷰를 수행하고 결과를 과장하지 않고 기록한다.

## 변경 전후 측정

새 삭제 동작은 기준 제품에 없어 삭제 완료 속도의 전후 비교는 지원되지 않는다. 기준0/미실행을 가상의 삭제 성능이나 개선율로 만들지 않는다. 변경될 이력 화면/VM의 기존 진입 처리 비용을 비교해 부가 경계의 영향을 관찰하며 속도 향상을 가정하지 않는다. 삭제/연결 행 수나 테스트 통과 수는 정확성 근거로만 분리한다.

- 관찰/가설: 현재 이력은 종료 기록 조회/선택과 summary를 표시한다. 새 삭제 확인 경계는 기존 진입에 불필요한 새 DB query/상태 작업을 추가할 수 있으므로 이를 동작 진입 전에 지연해 기존 비용의 회귀를 살핀다.
- 지표(ms): 실제 MainActivity의 home_history 클릭 직전→원래 종료 source의 이력 제목/내용/summary/버튼과 Compose idle 확인까지. 기존 SessionHistoryOpeningMeasureTest의 endpoint/타이머/원본 검사를 그대로 사용하고 새 session-deletion-entry-v1 namespace로만 분리한다. 입력 전달/semantics/검사 비용을 포함하며 순수 GPU/SDK/DB 시간이나 운전자 속도가 아니다.
- 기준 제품3903bc6, 고정 계측 revision은 준비 commit 뒤 기록한다. 같은 파일/메서드/namespace/조건으로 비교한다.
- 조건: 기존 Android14/API34 Pleos/JDK17.0.21 debug, 실제 SDK P/UX 해제, font1.0/라이트, 동일 원래 준비/종료9/관찰15/메모0와 고정 카탈로그. 새 Activity 하나에서 Home→이력→close→Home,5회 워밍업 뒤30회 웜 진입. 매 표본 새 Activity/콜드 앱 시작이 아니다. 캐시를 지우지 않고 무거운 Gradle/AVD는 순차 실행한다.
- 전후 순서: 기준→제품 변경→비교. SDK/DB/OS/캐시/발열의 순차 편차는 제거되지 않아 분포 겹침 시 개선을 확정하지 않는다. 원본 확인/JSON/닫기/복원은 기존 계측의 타이밍 밖 경계를 유지한다.
- 실패/제외: 기존20초 endpoint와 전체 원본/선택/환경/P+UX/source 불일치, 예외/복원 실패는 실패 보존 후 중단. 실패/누락/미실행/제외 분리, 느린 표본 제외/0 대체/완료 파일 덮어쓰기 금지. 이전 이력 실측 파일은 그대로 보존한다.
- 비교: 전후 원값/표본 수/중앙값/Q1/Q3/IQR/min/max, 절대 차이/기준 대비 관찰 변화와 한계를 기록한다. 기준0 상대율 없음. 새 기능의 정확성 완료와 성능 향상 확정은 구분한다.
