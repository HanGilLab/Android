## 목표와 범위

실제 홈/이력이 쓰는 `RoomPracticeSessionRepository.observeSessions`는 raw Entity를 바로 모델로 변환한다. 원래 REAL 버전이나 Int 밖 INTEGER가1로 읽히면 종료 원본이 정상 버전1과 같은 코스로 요약될 수 있다. 관찰에 사용한 데이터라도 원래 SQLite 자료형을 잃은 뒤의 domain 검증만으로는 이를 검출할 수 없다. 정상 행을 일부만 발행하거나 손상 행을 숨겨 빈/부분 이력으로 복구하지 않는다.

같은 저장 경계의 시작은 activeSlot=1을 찾는다. 실제 REAL1.75의 미종료 행은 모델에서1로 읽히지만 SQL 조회에는 없어, 이전에 표시된 정상 준비로 시작하면 두 번째 논리 활성 행이 만들어질 수 있다. 관찰 오류만 막아서는 P/UX만 재확인하는 stale 시작의 DB 변경을 막지 못하므로, 같은 시작 transaction에서 checked active 원본과 unfinishedCount를 함께 확인한다. 유효 active가 있으면 정확히 하나여야 하고, 없으면 미종료 행이0이어야 한다. 두 권한 확인과 정상 AlreadyActive/준비/동시 시작 계약은 유지한다.

제품 변경 전 실제 Room/SQLite fixture에서 원래 타입/값과 Flow/요약 혼입, active 조회 누락/중복 시작을 재현한다. 확인 뒤 동일 SQL의 원시 저장 검증 projection을 관찰/active 읽기에 연결한다. 기존 쓰기 guard, raw DAO/Entity/schema/domain/화면/SDK/권한과 열린 PR83/86/87은 변경하지 않는다. 기기/ADB/CUA/native/SDK/JDI 진단은 수행하지 않는다.

## 기준 실행과 최소 구현

제품 미변경14개에서 손상12개는 실제 fixture 타입/값과 active 조회/미종료 수 확인 뒤 기대 오류 assertion에서 실패했고 정상2개는 통과했다. 숫자 버전6개는 정상 종료 원본과 같은 맥락으로 합산됐으며, REAL 슬롯은 raw active 조회에 없는데도 Started를 반환해 논리 미종료2개와 원시 자료/sequence 변경이 생겼다. 손상 active/복수 미종료는 정상 AlreadyActive로 응답했다. 컴파일/fixture 오류나 취소를 RED로 계산하지 않았으며 원래 소스/XML/로그를 비공개로 보존했다.

확인 후 같은 SQL에서 원래 자료형/버전 범위를 판정하는 `PracticeSessionRow`와 공통 SELECT를 추가했다. 원래 타입을 검사하기 전에 일부 행을 제외/복구하지 않고 전체 관찰을 오류로 전파한다. 시작은 같은 transaction에서 checked active 모델과 실제 미종료 수0/1의 일치를 확인해 조회에서 누락된 소유자나 복수 소유자를 정상으로 인정하지 않는다. 정상 active는 이전처럼 무관한 준비를 읽지 않고 AlreadyActive와 두 권한 확인을 유지한다. raw DAO/Entity/schema/기존 쓰기 guard/화면/SDK는 바꾸지 않았다. 기준과 바이트 동일한 검증 source의 수정 후14개가 모두 통과했다. 이후 진단 문구만 같은 내용으로 나누고 포맷한 최종 소스의 전체 verify 재실행도4단계 성공/종료0이다. 기존 준비/시작 경합/권한/취소/마이그레이션 회귀를 포함하며 최신 PR CI/Codex와 실제 병합은 별도로 확인한다.

README는 기존 strict finish와 권한 helper의 소스 anchor 한 곳만 실제107~147행으로 보정했다. 이를 원래104~144행으로 되돌리면 기준 README와 바이트 동일하며 네 사례/여섯 항목/실제 발췌/화면은 그대로다.

첫 SpotlessApply는 테스트 진단 문자열의140자 초과로 실패했다. 종료 코드를 먼저 확인하지 않고 시작한 첫 전체 verify도 같은 품질 오류에서 중단됐으므로 이후 전체 단위/빌드는 미실행이다. 그 실행 폴더에 복사된 XML은 앞선 focused 수정 후 결과이며 새 전체 검사 성공으로 계산하지 않는다. 원문/로그를 보존하고 진단 문자열만 같은 내용의 연결식으로 나눈 뒤 포맷/전체 검사를 다시 확인한다. 억제/기준 완화나 제품 처리는 바꾸지 않는다.
