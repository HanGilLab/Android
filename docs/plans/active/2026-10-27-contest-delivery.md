## 목표와 범위

공모전에서 설명하고 시연할 수 있는 앱과 제출 자료를 준비한다.
노션 12절의 ID별 체크리스트를 작업 기준으로 사용하고, 기능별 변경은 별도 계획과 작은 PR로 구현한다.
이 계획은 전체 출품의 상위 계획이며 체크리스트, 자동화 등록만으로 완료 처리하지 않는다.
초기 필수 작업은 53개였으며 반복 JDK C1 종료의 자가 점검으로 ENV-09를 추가했다. 현재 필수 54개, 선택 3개의 상태와 진행률은 노션에서 확인한다.

- 우선순위: 개발 환경과 기존 기능 재검증 → 지도, 내비, 세션, 복습 → 디자인, 사용성 → 출품 자료.
- 지도: 코스, 복습 지도와 Pleos 기본 내비 연동.
- 디자인: 민트, 크림, 둥근 카드와 길잡이 캐릭터. 장식 이미지는 주차 화면 중심으로 사용.
- 범위 제외: 결제, 기관 관리, 상용 운영, 운전 능력 자동 인증과 차량 조향, 제동 제어.
- 사용자 작업: 참가 정보 확정, 본인 서명, 실제 접수 이메일 발송과 접수 확인.

## 구현 단계

1. 기존 기획을 보존하고 중복 과제를 ID별 체크리스트로 통합한다. 현재 구현과 현재 환경 검증을 구분한다.
2. 2026-10-27~29: 개발 환경, 기존 동작, 지도와 내비 기술 조건을 확인하고 브랜드 방향을 정리한다.
3. 2026-10-30~11-04: 지도, 내비, 세션, 복습, 다음 연습을 구현한다.
4. 2026-11-05~07: 디자인, 이미지, 예외 처리, 사용성을 보완한다.
5. 2026-11-08~10: 전체 검증과 리뷰를 마치고 출품 자료를 완성한다.

자동 작업은 노션, AGENTS.md, 진행 중 계획, 관련 PR, CI를 읽고 진행 중 작업과 리뷰 결함을 우선 처리한다.
최신 커밋의 필수 검사, Codex 리뷰, 수동 검증과 지적 처리를 마친 PR만 자동 병합한다.
병합 후 main을 동기화하고 끝 커밋과 병합 여부를 확인한 작업 브랜치를 정리한다.
미실행, 실패, 미지원, 리뷰 제한을 성공으로 처리하지 않으며 사용자 변경을 보존한다.
출품 관련 자가 피드백은 근거와 완료 기준을 붙여 중복 없이 노션에 추가한다.

## SUB-19 수정 제출 절차 준비

- 목표와 범위: [수정 제출 절차, 확인표](../../submission/revision-checklist.md)에 공식 규정과 실제 사용자 확인 상태를 구분해 정리한다.
- 완료 기준: 동일 발신 주소, 전체 자료/서명 동의서 재첨부, 전원 CC, 수정 제목, 마감 전 최종본 기준을 확인하고, 현재 수정 필요 여부를 추정 없이 기록한다.
- 구현 단계: 공식 안내를 재확인하고 절차와 발송 전 확인표를 작성한 뒤 링크, 개인정보, 검사, PR 리뷰를 확인한다.
- 현재 상태: 최초 발송 이력, 참가 정보, 수정 대상, 재발송 필요 여부, 실제 발송/접수는 사용자 확인 전 미확인이다. 절차 준비를 실제 발송이나 접수 완료로 계산하지 않는다.
- 검증 근거: 2026-10-28 공식 제출 안내, 규정을 대조했다. 상대 링크, 현재 상태6개 미확인, 비공개 정보 미포함과 문서 내용을 독립 검토했다. Temurin17.0.21+9 기본 JIT의 전체 검사, 단위96개(실패/오류/건너뜀0), debug/unsigned release가 통과했으며 캐시/up-to-date 결과를 포함한다. 문서만 바꿔 새 앱 실기는 실행하지 않았다. 최초 Spotless 입력 직렬화 실패1회는 별도 보존했고 설정, 캐시 삭제 없이 독립 Spotless와 공식 전체 재검증이 통과했다. 근본 원인은 미확정이다. 최신 CI와 Codex 리뷰 결과는 이 문서 변경 PR에서 추적한다.
- 남은 작업: 실제 수정 발송이 필요하면 사용자가 최종 확인하고 대표자가 발송한다. 실제 발신/CC 주소, 서명 원본, 발송본은 공개 문서에 기록하지 않는다.

## 남은 문제와 인계

- 노션은 대기, 진행, 검증 대기, 차단, 완료로 관리하며, 완료 조건을 충족한 항목만 체크한다.
- 필수 작업 진행률과 선택 작업을 분리한다. 분모가 바뀌면 이유를 기록한다.
- 과거 Pleos 성공 기록을 현재 환경 준비의 증거로 쓰지 않는다.
- PR #5의 리뷰 후 UI 재검증 미완료 기록과 완료 계획의 통과 기록은 과거 시점의 불일치로 남긴다. 현재 재검증 결과를 별도로 기록하며, 확인되지 않은 과거 성공을 소급 확정하지 않는다.
- 서명 원본, 연락처, 로컬 경로, 기기 식별자, 인증정보를 노션, 저장소, 공개 산출물에 기록하지 않는다.
- 사용자 발송 확인 전에는 제출 완료로 표시하지 않고 발송 사실과 접수 확인을 구분한다.
- 자동 작업은 2026-11-10 종료 시점까지만 운영한다. 이후 미완료 작업을 자동 연장하지 않는다.
- 로컬 자동 작업에는 컴퓨터와 Codex 앱 실행이 필요하다.
- 2026-10-29 정합 확인: ENV-09의 JDK 준비와 SUB-11의 원본 공개 접근은 실제 검증, 관련 PR 병합으로 완료돼 각각의 계획을 `completed/`로 정리했다. 필수 완료 수는 기존 19/54를 유지하며 새 항목을 완료로 늘리지 않는다. 초기 설정 PR #1의 최신 head에는 Codex 완료 근거가 없어 초기 계획은 미완료로 보존한다.
