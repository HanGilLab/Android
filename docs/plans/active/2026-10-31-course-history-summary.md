- 관찰/가설: 현재 이력은 한 종료 snapshot씩 읽는다. 같은 수신 목록의 요약을 추가하면 계산/레이아웃 비용이 늘 수 있어 기존 진입이 유지되는지 비용/분포를 비교한다. 과거 최초 확대 timeout의 원인은 미확정이며 이번 가설이나 해결 대상으로 확정하지 않는다.
- 지표/단위: 실제 native UI 검사의 home_history 명시 클릭 호출 직전부터 이력의 history_ready 및 코스가 실제로 표시되고 Compose idle을 확인할 때까지 monotonic wall time(ms). 실제 생산 Activity/SDK/Room/화면을 사용한다. 계측의 클릭 전달/idle 대기/semantics 확인 overhead를 포함하므로 앱 내부 렌더 완료/프레임/GPU/SDK 성능이나 사용자 행동 속도로 해석하지 않는다.

## README 사례 선정

기존4개와 순서를 보존한다. 이번 요약은 기존 수신/선택 세대 경계를 사용하는 새 읽기 기능으로, 실제 난도/원인 증거/대안 판단/재현 가능한 해결에서 기존 안전/동시성/네이티브 View/SQLite 자료형 사례보다 우월한 근거가 생긴 경우에만 교체한다. 새 기능/기록 수/단위 검사 수나 최신성만으로 바꾸지 않는다. 최종 실제 결과 확보 뒤 다시 비교한다. 문서/사진 배치는 앱 실행 성능 변경이 아니므로 링크/실제 렌더/화면으로 검증한다.

## 남은 문제와 인계

과정 완료/삭제와 APP-08 전체, 실제 구간 복습/위치/내비, 독립 UX 조합과 기존 원래 head 리뷰는 별도 미완료다. 기존 종료 기록/시연 출처와 모든 원래 자료를 보존한다. 제외된 다른 저장소/문서나 완료된 이력 정리는 재개하지 않는다.

독립 읽기 검토에서 선택 source의 전체 일치/유효성/중복 거부, 같은7필드 문맥과 과제id/title별 집계, same-Ready 원자 발행 및 표시 경계에서 추가 확정 결함은 없었다. 이 검토는 최신 PR Codex 리뷰를 대신하지 않는다. 실제 UI는 전역 문자열이 아니라 각 index/tag로 원문과 개수를 대조하며 검사 실행은 아직 별도다.

## 최초 확대 실패와 재실행

확대 첫 실행1회는 외부 실행자가 HISTORY_AWAIT_D 신호 뒤90초 안에 실제 DDS D 전환을 보내지 않아 awaitDrive의 TimeoutCancellationException으로 실패했다. 실제 콘솔은 P였으며 이 실패를 앱 결함이나 D 잠금 성공으로 해석하지 않는다. 실패/캐시 사진을 별도로 보존했고, 실제 P와 원래 모든 자료/타입/순서/sequence/권한/기타 설정의 일치를 확인했다. 글꼴1.3/다크만 의도된 검증 조건으로 남아 있었다. 코드/성공 조건/timeout을 바꾸지 않고 신호에 맞춰 실제 D/P를 보낸 재실행은 전 항목을 통과했다. 최초1회 실패는 최종2개 성공에 합치지 않았다. 과거 최초 확대의 history_finished20초 timeout은 별도 원인 미확정으로 유지하며 이번 결과로 해결됐다고 주장하지 않는다.

## README 최종 사례 비교

새 기능은 기존 수신 목록과 선택 세대를 재사용한 읽기 요약이다. 기존4개가 보여 주는 차량 안전 판정, DB 동시성과 원자 저장, 네이티브 View와 비동기 수신 경합, SQLite 타입 손실의 원인/해결보다 더 강한 원인 증거나 판단의 난도를 새로 입증하지 않았다. 실제 계측도 성능 향상 근거가 아니므로 네 사례와 순서/코드 전체를 보존한다. 기록 수/단위 검사 수/최신성으로 교체하지 않는다. README에는 검증된 실제 패널 영역2장과 구현 기능만 추가하고 회귀 근거나 미측정 성과표를 넣지 않았다.

최종 실제 캡처/README/절차/계획 변경 뒤 JDK17 quality를 다시 통과했다. 기준 계측 파일은b98f31a와 바이트 동일하고, 실기/비교 검증 제품eac86f6 이후 app/core/feature/scripts/build 소스는 변경하지 않았다.
