# 주차 화면의 여백과 컴포넌트 시각 개선

- 상태: 진행 중
- 요구사항: 사용자 피드백에 따른 홈, 목표/코스/과제 선택과 지도의 정보량 및 행동 위계 개선, DES-06 부분 범위

## 목표와 범위

현재 실제 앱 화면의 과도한 빈 공간, 비슷하게 이어지는 채색 카드와 큰 버튼의 정보 위계를 정리한다. 최신 사용자 지시에 따른 토스 스타일의 중립 배경, 단순한 카드와 선명한 주요 버튼, 한길 길잡이 리소스를 적용하면서 화면별 주요 행동, 선택 상태와 설명의 밀도를 구분한다. 실제 앱의 홈과 준비 흐름에서 개선 전후 화면을 비교한다.

이번 변경은 Compose 화면과 시각 컴포넌트, 사용자 요청에 따른 README 문제 해결 근거 범위다. 기존 동작, 사용자 데이터, 출처 구분, 주차와 UX 제한의 동시 확인 조건은 유지한다. 새 기능과 SDK 권한, 관찰 수집은 추가하지 않는다. 공개 이미지에는 실제 변경 화면의 검증된 앱 영역만 사용한다.

## 추가 사용자 피드백과 UX 재조정

여백과 색상만 조정한 중간 화면을 기준으로 사용자가 전체 텍스트량과 읽기 부담을 다시 지적했다. 이 패치를 최종안으로 간주하지 않고 홈의 다음 행동, 선택 단계와 지도 상태 중심으로 정보 위계를 다시 조정한다. 반복되는 여정 설명, 데이터 범위 안내와 부가 정보는 필요한 시점에만 제시한다. 시연 구분, 미확인 잠금과 실제 기록의 의미는 보존한다. 사용성이나 주의 분산 개선율은 측정하지 않았으므로 주장하지 않는다.

중간 앱의 실제 준비 흐름 1개를 확인했고 원래 DBv2에서 v3로 전진 마이그레이션 후 기존 준비 1행과 연습 3행 전체 필드, 권한과 표시 설정이 보존됐다. 이 캡처는 비교 기준이며 새 UX 최종 검증으로 기록하지 않는다.

### 최종 디자인 방향

사용자가 앱 전체를 토스 스타일로 조정하도록 지시했다. 사용자의 후속 정정으로 토스 스타일은 구성과 정보 위계에 한하며 한길의 민트/크림 브랜드 색상을 유지한다. 글자 크기와 화면 가장자리 및 요소 사이 간격도 실제 읽기 기준으로 더 키운다. [TDS 소개](https://tossmini-docs.toss.im/tds-mobile/)와 [공식 컬러 시스템 설명](https://toss.tech/article/tds-color-system-update)을 참고해 의미별 색상 토큰, 일관된 컴포넌트와 라이트/다크 대비를 적용한다. 한길의 기존 브랜드를 유지하고 외부 서비스용 SDK나 그래픽, 계정 기능은 추가하지 않는다. 정보량을 줄인 중간 UI는 최종 디자인 검증으로 계산하지 않는다. 최종 핵심 본문/상세 버튼은 24sp, 선택 제목은 28sp이며 화면 바깥 여백은 48dp, 카드 안쪽은 32~36dp로 넓혔다. 이 최종 소스로 JDK17 전체 검사/단위143개(실패/오류/건너뜀0)/debug 및 unsigned release/계측 APK 빌드를 통과했다. 실제 화면 검증은 후속이다.

## 완료 조건

- [ ] 실제 기본 화면에서 제목과 주요 행동, 선택 항목과 보조 설명이 분명히 구분되며 기존에 비해 불필요한 채색/빈 공간이 줄어든다.
- [ ] 기본/확대 글자와 다크 테마의 줄바꿈, 버튼/선택 영역, 스크롤과 선택지의 두 열/한 열 배치를 확인한다. 기본 접힘, 펼침 접근과 주행 잠금/복귀 후 상세 초기화를 확인한다.
- [ ] 실제 P/UX 허용, D 잠금과 P 복귀에서 상세 내용/장식과 작성 중 선택의 상태를 확인하고 기존 자료를 보존한다.
- [ ] JDK17 전체 검사, 변경 동작 계측, 최신 PR CI와 Codex 리뷰를 통과한다.

## 구현 단계

1. 현재 실제 화면과 공통 토큰/컴포넌트, 화면 코드를 읽고 고칠 시각 경계를 정한다.
2. 사용자 동작과 상태 조건을 보존하며 현재 단계의 주요 행동과 짧은 선택, 필요한 시점의 상세 공개로 정보 위계를 조정한다. 지도 안내도 시연 구분과 상태를 유지하며 축약한다.
3. 무거운 빌드와 Pleos 검증을 순차 실행하고 실제 정상/잠금/복귀와 자료 보존을 확인한다.
4. 검증된 실제 앱 영역만 캡처하고 출처와 상태를 구분한다.
5. README 문제 해결을 정확히 4개로 작성한다. 문제, 원인, 해결, 결과, 대체안/회고, 코드 순서를 지키고 관련 테스트에서 산출한 수치와 재현 근거를 연결한다.

## README 최초 4개 선정 근거

- 최신 차량 상태와 UX 상태의 비동기 경계: 화면 표시만 믿을 때 남는 조작 경합을 실제 처리 시점에서 막는 판단을 보여준다. 9개 상태 조합과 오래된 P/새 D 회귀 근거가 있다.
- 연습 시작과 종료의 원자성: UI 중복 클릭 방지를 넘어 저장소 트랜잭션과 유일 인덱스로 동시성과 데이터 일관성을 다룬다. 4개 동시 요청과 시작/종료 중 잠금 전환의 저장 결과를 검증한다.
- 지도 View 생명주기의 오래된 콜백: 요청 번호만으로 구분되지 않는 같은 요청의 View 재생성을 별도 토큰으로 구분한다. 실패 뒤 콜백과 재생성/재시도를 분리한 회귀 테스트가 있다.
- SQLite 물리 자료형과 SDK 읽기 상태 보존: 선언된 INTEGER/Boolean만 믿으면 손상된 REAL/TEXT가 정상 값으로 축약되는 결함을 실제 SQL 입력으로 드러냈다. 16개 논리 손상 변형, 4개 물리 자료형 변형과 두 이전 스키마 마이그레이션을 검사한다. 저장 기반만 구현됐으며 실제 SDK 수집 성과로 표현하지 않는다.

README에 기존 사례가 없어 최초 4개를 구성한다. 위 4개는 단순 화면 배치보다 비동기 상태, 원자성, 생명주기, 자료형 경계를 각각 분리해 원인과 판단을 증명한다. 이후 새 근거가 나오면 해당 기존 사례와 비교하고 더 강한 사례만 교체하며 교체 개수는 제한하지 않는다. 채용 효과 자체를 실증한 수치로 주장하지 않는다.

### 정보량 축소 후 자동 검증

JDK 17에서 전체 품질/모듈 경계/Lint, JVM 및 Android 단위 테스트 143개, debug/unsigned release와 변경 동작 계측 APK 빌드를 통과했다. 기존 테스트 보고서 집계는 사례별 2/11/5/11개와 마이그레이션 2개, 실패/오류/건너뜀 0개를 구분한다. 접힘/펼침, 선택지 배치와 P→D→P의 상세 초기화는 새 UI 계약에 맞춰 계측에 반영했고 실제 실행은 후속으로 남아 있다. 임시 JUnit fixture 14종 감사로 누락/실패/건너뜀/손상 보고서를 성공으로 집계하지 않는 것과 절대 경로 비노출을 확인했다.

### 최종 테마 검증 중 수정

중립색 전환 후 첫 전체 검사에서 Material의 `contentColorFor`가 같은 색상값을 가진 variant와 high container를 구별하지 못해 본문 색상을 잘못 선택하는 회귀를 발견했다. 대비 수치 자체만으로는 발견되지 않는 의미별 토큰 충돌이었다. variant 색상을 분리하고 기존 대비/본문 색상 결정 테스트를 그대로 유지해 전체 검사와 계측 APK 빌드를 다시 통과했다. 단위 테스트 143개, 실패/오류/건너뜀은 각각 0개이며 실제 화면 검증은 별도다.

### 개발 중 발견과 수정

- Compose의 중첩 레이아웃에서 바깥 제약 수신자를 암묵적으로 참조한 컴파일 오류를 조건 값의 명시적 계산으로 수정했다. 최종 전체 검사와 계측 APK 빌드는 통과했다.
- 실행 중인 검증 스크립트에 집계 단계를 삽입해 그 실행의 파서 오프셋이 어긋난 별도 작업 오류가 있었다. 스크립트 구문을 확인하고 고정된 소스로 전체 검사를 다시 완료했다. 앱 오류나 테스트 통과로 바꿔 기록하지 않는다.
- 근거 집계 도구는 기존 JUnit 결과의 실제 테스트별 실패/오류/건너뜀과 시각을 검사한다. 읽기 오류의 절대 경로 노출, 잘못된 시각/이름을 정상으로 취급하는 결함을 독립 감사로 발견해 수정했다.

### 실제 실행과 마무리 범위

`1344ba4`의 최종 브랜드색/글자/여백에 대해 실제 Android 시나리오 13개가 건너뜀 없이 통과했다. Virtual Console은 실제 브라우저에서 DDS ONLINE과 P/D 전환을 확인했고 앱의 SDK 잠금 및 복귀와 교차 확인했다. 기본/1.6배/다크 홈과 선택/펼침/접기/작성 취소, 주행 중 상세 제거와 P 복귀 후 선택 유지 및 상세 초기화, 지도 재생성, 권한 미허용 상태를 확인했다. 별도 일회성 앱에서 신규 준비 저장/시작/종료/재생성을 실행해 원래 앱 기록을 변경하지 않았고 검사 앱은 제거했다. 원래 데이터 전체 필드, 권한/런타임 플래그와 글자/테마를 비교해 보존했고 소유한 AVD/포워딩만 종료했다. 실제 SDK 수집기/위치/조향 관찰 성공으로 계산하지 않는다.

실물 캡처에서 선택 카드의 터치 표시가 둥근 모서리 밖으로 그려지는 부분을 발견했다. 같은 카드 shape의 clip을 selectable 앞에 적용해 표시 경계를 맞췄다. 상태/콜백/최소 터치와 radio 역할은 그대로이고 이 마이너 변경의 JDK17 전체 검사/단위143개(실패/오류/건너뜀0)/debug 및 unsigned release/계측 APK 재빌드는 통과했고 실제 선택 캡처를 추가로 확인한다.

이번 정보량/가독성 조정과 색상 토큰 충돌은 새로운 후보로 검토했지만, 사용성 효과나 전후 성능을 측정한 근거가 없다. 기존 4개가 비동기 상태/원자성/생명주기/손상 데이터 경계를 더 독립적이고 재현 가능하게 보여 주므로 README 사례를 유지한다. 더 강한 새 근거가 나오면 해당 사례와 다시 비교한다.

## 남은 문제와 인계

전체 DES-06, 미구현 복습/완료와 지도 경로 기능을 이번 시각 개선으로 완료 처리하지 않는다. 개인별 환경과 데이터 원문은 비공개 기록에만 보존한다.
