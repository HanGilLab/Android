# 세션 차량 관찰값 저장 기반

- 상태: 진행 중
- 요구사항: 공모전 APP-04의 독립적인 저장 기반 준비 (비공개 작업 명세)

## 목표와 범위

활성 연습 세션에 연결할 차량 관찰값의 domain 계약과 Room 저장 기반을 추가한다. 현재 VehicleGateway는 최신 상태를 전달하므로 모든 SDK 이벤트를 빠짐없이 기록한다고 설명하지 않는다. 기어, 방향지시등과 브레이크의 실제 관찰 상태, 연결 상태와 앱 관찰 시각을 그대로 보존하며 SDK 발생 시각, 위치와 조향 입력은 추정하지 않는다.

이번 변경은 저장 계약과 어댑터, 데이터 보존 마이그레이션을 검증하는 선행 작업이다. 제품 수집기, 새 권한, 백그라운드 서비스, 화면과 사용자의 기존 기록 내용은 변경하지 않는다. APP-04 전체와 MAP-01의 기존 최종 리뷰 대기는 별도 미완료로 유지한다.

## 완료 조건

- [x] 관찰값의 Available/Unknown/Unsupported/PermissionDenied/Error와 연결 상태를 구분해 원형 복원한다. 누락 값을 정상 값이나 0으로 바꾸지 않는다.
- [x] 세션 참조와 활성 상태를 같은 트랜잭션에서 확인하고 없는 세션, 종료 세션과 잘못된 시각을 구분한다. 저장 순서는 벽시계 역행에 영향받지 않는다.
- [x] Room v2의 격리된 복사본을 새 스키마로 전진할 때 기존 준비와 모든 세션을 보존하고 새 관찰 테이블은 비어 있다. 외래키와 취소/동시 종료 경계를 검증한다.
- [ ] JDK17 전체 검사와 실제 장치의 보존 마이그레이션/격리된 DB 계측, 최신 PR CI와 Codex 리뷰를 통과한다.

## 구현 단계

1. 기존 domain/Room/SDK의 상태 전달과 세션 경계를 확인하고 저장 계약을 정한다.
2. 활성 세션에만 추가하는 어댑터와 명시적 마이그레이션, 의미 있는 상태/순서/경계 검사를 추가한다.
3. 무거운 Gradle 검사 뒤 기존 전용 장치의 독립 검사 패키지에서 원본 자료를 보존한 채 검증하고 실제 결과와 미실행 범위를 기록한다.

## 검증 결과

| 명령 또는 시나리오 | 결과 | 근거 |
|---|---|---|
| JDK17 `./scripts/verify.sh` | 통과 | 품질, 모듈 경계, Lint, 단위143개(실패/오류/건너뜀0), debug와 unsigned release 빌드 |
| v1/v2 자료 보존 마이그레이션 | 통과 | JVM의 기존 준비/세션 보존과 실제 Android의 격리 v2 복사본 전진, 새 관찰 테이블 비어 있음 |
| 실제 장치의 격리 DB 저장/복원 | 통과 | 새 검사 패키지의 상태/출처/순서와 재열기, 종료 뒤 거부, 복사본 마이그레이션의 개별 계측2개. 건너뜀0. 원본 앱/자료는 유지 |
| 최신 PR CI/Codex 리뷰 | 대기 | PR 생성 뒤 실제 최신 커밋을 확인 |

초기 전체 검사142개 통과 후 독립 검토에서 SQLite REAL/TEXT가 Long 읽기 중 정상 값으로 변환될 수 있는 경계를 확인했다. 물리 타입을 함께 조회하는 projection과 실제 SQL 오염값 회귀를 추가해 최종143개 전체 검사를 통과했다. 의미 있는 결함 보강과 최종 통과를 구분한다.

자세한 저장 의미와 계측 선택 조건은 [실행 안내](../../development/vehicle-observation-storage.md)를 따른다.

## 남은 문제와 인계

제품의 관찰 수집, 화면 이탈/내비 전환 중 수집, 위치 신뢰도와 SDK 발생 시각, 조향 입력과 복습 화면은 후속 범위다. 저장 기반 검사에서 만든 자료는 검사 전용이며 실제 사용자 주행 자료로 표시하지 않는다. 개인별 원문 데이터와 환경 근거는 공개 산출물에 넣지 않는다.
