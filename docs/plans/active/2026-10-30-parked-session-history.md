# 주차 중 종료 연습 이력 열람 연결

- 상태: 진행 중
- 요구사항: APP-08의 종료 기록 열람 부분. 과정 요약과 삭제, APP-07 및 APP-08 전체는 별도 미완료다.
- 기준 커밋: c545a59083efedd41f49badc7a372006ae7157a7

## 목표와 범위

현재 홈은 최근 종료 세션 하나만 보여 지난 기록을 확인할 수 없다. 이미 검증된 PracticeSessionRepository.observeSessions의 저장 생성 순서와 당시 스냅샷을 사용해, 주차 중 종료된 기록을 한 번에 하나씩 열람한다. 현재 준비나 현재 카탈로그로 과거 목표/코스/과제를 다시 해석하지 않는다.

APP-08의 APP-07 전체 선행 표시를 전체 구현 대기로 해석하지 않는다. 종료 기록의 기존 읽기 계약만 사용하는 독립 범위이며 새 위치/지도/내비 API, 권한, DB 스키마나 저장/삭제 동작은 추가하지 않는다. 실제 도로와 지도 구간 복습, 운전 능력 점수, 과정 완료 판정, 이전 기록의 관찰/메모 편집 및 삭제는 범위 밖이다.

## 완료 조건

- [ ] 실제 P와 UX 허용을 모두 확인해야 종료 기록을 읽고 열람한다. 주행/끊김/미확인/거부에서는 잠금을 유지하고 늦은 UI 조작을 실행 직전에 차단한다.
- [ ] 종료 기록만 저장 생성 순서대로 보여 준다. 벽시계로 다시 정렬하지 않고 당시 목표/코스/과제, 시연 여부, 시작/마무리 버튼 시각을 구분한다.
- [ ] 빈 종료 이력, 로딩, 읽기 실패/스트림 종료와 선택한 기록 변경을 정상 기록으로 대체하지 않는다. 새로운 저장 앞에서도 선택 ID를 유지하고 선택이 사라지면 명시적으로 다시 선택하도록 한다.
- [ ] 잠금/이탈/재시도/재생성 경계에서 이전 결과와 선택 조작이 새 상태를 덮지 못한다. 열람은 원래 준비와 모든 기록/관찰/메모를 쓰거나 삭제하지 않는다.
- [ ] JDK17 ./scripts/verify.sh와 변경 경계 검사, 실제 Pleos의 기본1.0/라이트와 확대1.3/다크에서 전체 저장 이력 대조/이동/닫기/재진입/재생성/실제 D-P 잠금을 확인한다. 실기 빈 이력/오류 미주입은 구분한다.
- [ ] 원래 schema4 준비1/종료9/SDK 관찰15/메모0의 모든 행/필드/순서/sequence와 권한, 글꼴/야간/IME/프록시를 보존하고 소유 리소스만 종료한다.
- [ ] 현재 head의 필수 CI/Codex 리뷰와 정책 병합, main ff-only/브랜치 정리, Notion 검증을 확인한다.

## 구현 단계

1. 최신 체크리스트/진행 계획/lease와 실제 리뷰/CI, 공식 안내를 확인한다.
2. 종료 기록 열람의 독립 ViewModel/상태/검사를 추가하고 홈의 안전한 진입과 별도 화면을 연결한다.
3. 실제 저장 데이터와 SDK, 화면/생명주기를 검증하고 원래 상태를 대조한다.
4. 실제 검증이 끝난 화면만 README에 반영하고 기존4사례와 비교한다. 최신 PR 검사/리뷰 후 병합하고 기록을 마무리한다.

## 변경 전후 측정

기준 앱에는 최근 한 개 외의 종료 기록을 열람하는 동등한 경로가 없다. 기존 병목의 최적화가 아닌 미완료 제품 연결이므로 전후 성능 개선으로 주장하지 않는다. 기존 전체 목록 계약을 재사용하되 조회 지연/메모리/호출량의 개선율을 만들지 않는다. 후속 최적화는 실제 병목을 관찰한 뒤 측정 계약에 따라 기준값부터 실행한다.

- 병목과 관찰 근거, 개선 가설: 과거 종료 기록 UI 연결 부재, 성능 가설 없음.
- 지표와 단위, 비교 방향: 성능 비교 적용 제외. 실제 저장 스냅샷/순서/상태/잠금/보존을 확인한다.
- 기준/비교 커밋: c545a59, 비교는 최종 구현 source/head로 기록한다.
- 조건: 기존 전용 Pleos debug, 원래 데이터 보존, 기본1.0/라이트와1.3/다크, 실제 P+UX 허용 및 D/P, 새 권한 없음.
- 표본/순서/제외: 정확성 시나리오이며 성능 표본은 수집하지 않는다. 실패/미실행/미지원과 성공을 분리한다.
- 원값/재현: 기기/저장 원문은 ignored 비공개 근거에 보존하고 공개에는 정제 결과만 남긴다.
- README 문구/화면 배치는 앱 실행 경로를 바꾸지 않는 문서 변경이다. 실제 화면, 코드 링크와4사례 순서를 검증하며 성능 측정 적용 제외다.

## README 사례 선정과 비교

기존4개와 순서를 보존한다. 새 이력의 이전 안내 reset과 live 거부 뒤 D/P 합쳐짐 경합은 실제 RED로 원인을 좁혔지만 기존3번이 이미 수신, 조회 세대, 원자적 준비/렌더와 native View 토큰까지 다루므로 같은 stale callback 문제군의 더 좁은 경계다. 1번의 P+UX 안전 판단, 2번의 DB 트랜잭션/유일 인덱스/당시 스냅샷, 4번의 SQLite 변환 전 물리 자료형 검증을 대체하면 기술 역량의 폭이 줄고 경합 사례가 중복된다. 새 기능, 코드량, 검사 수나 최신성을 이유로 교체하지 않는다. README11개 코드 발췌와 링크가 현재 실제 소스에 일치함을 재확인했다. 회귀 집계와 미측정 성과표는 README에 넣지 않는다.

## 남은 문제와 인계

구현/최종 검증과 최신 PR 리뷰는 미완료다. 과정 요약, 삭제와 APP-07/APP-08 전체, 실제 도로/내비 및 독립 UX 조합은 별도 미완료로 유지한다. 원래 이력 정리와 다른 저장소/문서는 재개하지 않는다.
