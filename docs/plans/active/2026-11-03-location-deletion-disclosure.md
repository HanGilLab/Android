- 상태: 실제 UI RED 확인, 경고 수정과 전체 자동 검증 완료, 두 테마 GREEN 대기
- 요구사항: APP-08 P1의 연결 위치 자료 삭제 범위 고지
- 기준 main: `6b85c6b5d76a21dd84c772670f42e6868607cd35`

## 목표와 범위

삭제 확인창에 실제 CAS/cascade 대상인 위치 표본과 수집 상태를 명시한다. 기존 차량 관찰, 메모, 배경 실행과 마무리 선언, 이 기기에서 영구 삭제하며 복구할 수 없다는 문구는 유지한다. 추가 개수 행이나 입력/탐색 단계를 만들지 않고 경고 문자열만 고친다. 삭제 저장소, source/nonce/P+UX/생명주기 검사와 schema는 바꾸지 않는다.

먼저 제품 경고를 그대로 둔 상태에서 실제 Route/ViewModel/Room과 독립 문구 기대값으로 누락을 확인한다. UUID 소유 합성 DB만 사용하고 MainActivity/앱 그래프/실제 SDK/위치 공급자/기존 자료를 읽지 않는다. 별도 Fused 권한, 실제 위치 관찰과 JDI는 사용하지 않으며 이전 실제 SDK 검증의 소비된 승인/실행 범위와 구분한다.

## README 사례 비교

이번 고지는 기존 1번 source/읽기 소유권과 2번 확인된 삭제 CAS/rollback의 사용자 설명을 맞추는 좁은 정확성 보강이다. 현재 네 사례의 비동기 상태, 생명주기와 실제 native 입력 근거보다 강한 독립 제품 결과나 새 실측 성능을 만들지 않으므로 README의 정확한 네 사례, 순서/코드/링크/이미지를 유지한다.

## 남은 문제와 인계

기존 SessionDeletionFlowTest는 schema4 기대값과 위치 snapshot 누락이 있어 이번 한정 fixture에 현재 schema7, 선택/보존 세션의 위치 자료와 실제 원형 복원을 확인하도록 보완한다. 기존 SDK 실기 suite 전체나 실제 위치 실행을 다시 수행한 것으로 표시하지 않는다. 제품 경고는 실제 baseline RED가 확보될 때까지 바꾸지 않는다. 기기/설치/실제 UI 실행은 별도 담당자가 맡고 실행 전까지 성공으로 기록하지 않는다.


## 실제 기준 실행과 실패 구분

호스트 권한 확인 명령이 지원되지 않아 첫 사전 검사가 중단됐고, 그 시점의 설치/실제 테스트 실행은 0회였다. 지원 코드를 보강해 새 합성 fixture에 들어가기 전에 실제 targetContext의 FUSED_LOCATION 미허용을 확인하고 고정 phase를 남기도록 했다. 원래 기준 APK/실패 기록과 새 지원 APK를 따로 보존했다.

새 지원 APK의 첫 실제 실행은 테스트 시작과 phase가 없는 Process crashed로 끝났다. 원인은 아직 확인되지 않았으며 경고 누락 RED나 테스트 성공으로 세지 않는다. 원래 APK/소스를 그대로 두고 재설치나 재부팅 없이 한 번 재시도한 두 번째 실행에서 실제 테스트 1개가 시작됐고 DELETE_LOCATION_DISCLOSURE_MISSING으로 실패했다. FUSED_DENIED, RESOURCES_APPLIED, CONFIRMATION_VISIBLE 뒤 RESOURCES_RESTORED와 FIXTURE_CLOSED를 모두 확인해 실제 경고 누락과 원형 정리를 함께 기록했다.

이 RED에서는 경고 뒤에 있는 취소/잠금/삭제 단계까지 실행됐다고 주장하지 않는다. 해당 단계는 같은 검증 소스와 동결한 AndroidTest APK의 GREEN에서 별도로 확인한다. 실제 SDK 호출, 새 위치 권한과 JDI는 0이며 이전 실제 SDK 검증의 소비된 ledger도 그대로 유지됐다. 공개 문서에 원문 장치/사용자/경로/좌표와 비공개 실행 로그를 넣지 않는다.

이번 새 근거는 삭제 범위의 한 문장을 맞추는 좁은 의미 정확성이다. 기존 README 1번 종료 원본/읽기 소유권, 2번 삭제 CAS/rollback, 3번 지도/native 입력 소유권, 4번 기록 소유권 반환 순서의 더 넓은 상태/생명주기 근거를 교체하지 않는다. 실제 Android UI의 각 테마 단일 실행은 반복 안정성, 실제 위치 SDK나 사용자 성과의 증명이 아니다.
