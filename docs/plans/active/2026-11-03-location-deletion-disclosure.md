# 종료 기록 삭제의 위치 표본/수집 상태 고지

- 상태: 실제 UI RED와 전체 자동 검증 완료. GREEN 사전 조건 미충족으로 기본 라이트/확대 다크 수동 검증 보류, PR은 열린 상태로 미완료 유지
- 요구사항: APP-08 P1의 연결 위치 자료 삭제 범위 고지
- 기준 main: `6b85c6b5d76a21dd84c772670f42e6868607cd35`

## 목표와 범위

삭제 확인창에 실제 CAS/cascade 대상인 위치 표본과 수집 상태를 명시한다. 기존 차량 관찰, 메모, 배경 실행과 마무리 선언, 이 기기에서 영구 삭제하며 복구할 수 없다는 문구는 유지한다. 추가 개수 행이나 입력/탐색 단계를 만들지 않고 경고 문자열만 고친다. 삭제 저장소, source/nonce/P+UX/생명주기 검사와 schema는 바꾸지 않는다.

먼저 제품 경고를 그대로 둔 상태에서 실제 Route/ViewModel/Room과 독립 문구 기대값으로 누락을 확인한다. UUID 소유 합성 DB와 직접 구성한 화면 모델만 사용하고 MainActivity/실제 SDK/위치 공급자/기존 자료를 읽지 않는다. 기본 Application 시작의 Hilt lazy provider 구성은 이뤄지지만 검증은 SDK client를 요청하지 않는다. 위치 권한 요청, 실제 위치 관찰과 JDI는 사용하지 않는다. 합성 검증을 실제 SDK 동작이나 사용자 성과로 확장해 해석하지 않는다.

## 변경 전후 측정

이번 변경은 이미 삭제되는 연결 자료의 범주를 고지하는 의미 정확성 수정이다. 화면 경로, 조작 단계와 속도를 최적화하지 않으므로 성능/사용 흐름 속도의 전후 측정을 적용하지 않는다. 변경 전후 문구와 합성 자료 보존/삭제의 관찰을 정확성 근거로 쓰며, RED/GREEN 개수나 잔존 행 수를 성능 개선 수치로 바꾸지 않는다.

## README 사례 비교

이번 고지는 기존 1번 source/읽기 소유권과 2번 확인된 삭제 CAS/rollback의 사용자 설명을 맞추는 좁은 정확성 보강이다. 현재 네 사례의 비동기 상태, 생명주기와 실제 native 입력 근거보다 강한 독립 제품 결과나 새 실측 성능을 만들지 않으므로 README의 정확한 네 사례, 순서/코드/링크/이미지를 유지한다.

## 남은 문제와 인계

기존 SessionDeletionFlowTest는 schema4 기대값과 위치 snapshot 누락이 있어 이번 한정 fixture에 현재 schema7, 선택/보존 세션의 위치 자료와 실제 원형 복원을 확인하도록 보완한다. 기존 SDK 실기 suite 전체나 실제 위치 실행을 다시 수행한 것으로 표시하지 않는다. 제품 경고는 실제 baseline RED와 원형 정리를 확보한 뒤에만 변경했다. 실제 UI 검증은 별도 성공 근거를 확보한 경우만 성공으로 기록한다.


## 실제 기준 실행과 실패 구분

초기 사전 검사가 중단된 시도는 실제 테스트 실행 0회로 별도 보존했다. 첫 실제 실행도 테스트 시작 전에 중단돼 의미 RED로 세지 않는다. 동일한 고정 제품/검증 APK를 유지한 별도 재실행에서 실제 테스트 1개가 시작됐고 DELETE_LOCATION_DISCLOSURE_MISSING으로 실패했다. 실제 확인창 표시 뒤 독립 문구 기대값의 누락과 Resources 원형 복원, 격리 DB 종료를 확인했다. 각 원래 실행 결과와 상세 원인은 비공개 근거에 보존한다.

이 RED에서 경고 뒤의 취소/잠금/삭제 단계까지 실행됐다고 주장하지 않는다. 해당 단계는 같은 검증 소스와 고정 AndroidTest APK의 GREEN에서 따로 확인해야 한다. 실제 SDK 호출이나 위치 권한 요청 없이 합성 fixture만 사용한 근거이며 실제 SDK 수집이나 사용자 성과로 확대하지 않는다.

## GREEN 사전 조건과 병합 보류

수정 뒤 GREEN 사전 검사의 필수 조건을 확인하지 못해 제품 설치와 실제 테스트 실행 전에 중단했다. 기본 라이트와 확대 다크 GREEN은 모두 미실행이며 추가 시나리오를 실행하지 않았다. 소유한 합성 자료의 정리와 원본 보존 확인은 완료했고, 검증을 보류한 상세 환경 원인과 복구 기록은 비공개 근거로 분리했다.

제품 변경은 경고 한 줄이다. 전체 JDK17 verify와 최종 debug APK 빌드는 통과했고 고정 AndroidTest APK는 재빌드하지 않았다. 전체 resource ID, 앱 DEX, native 라이브러리와 binary manifest 호환성도 확인했지만 이 검사는 실제 두 테마 GREEN을 대신하지 않는다. PR은 열린 상태, 계획은 active/미완료로 유지하고 실제 두 테마 검증이 끝나기 전까지 병합을 보류한다.

이번 새 근거는 삭제 범위의 한 문장을 맞추는 좁은 의미 정확성이다. 기존 README 1번 종료 원본/읽기 소유권, 2번 삭제 CAS/rollback, 3번 지도/native 입력 소유권, 4번 기록 소유권 반환 순서의 더 넓은 상태/생명주기 근거를 교체하지 않는다. README 네 사례와 제품/테스트/APK는 추가로 바꾸지 않는다.
