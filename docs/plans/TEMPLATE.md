# 작업 이름

단순 수정은 별도 계획 파일 없이 PR 본문에 적는다. 여러 경계를 나눠 진행할 때만 이 템플릿을 사용한다.

- 목표와 실제 문제:
- 변경 범위:
- 관찰 가능한 완료 기준:
- 차단된 부분과 독립적으로 진행할 부분:

## 구현과 검증

필요한 단계와 바뀐 동작의 검증만 적는다. 실행 결과/실패/미실행은 해당 PR에 기록하고 복사하지 않는다. 종료 보고용 문서나 별도 PR은 만들지 않는다.

## 측정이 필요한 경우

실제 성능이나 사용 흐름을 최적화할 때는 변경 전에 병목/가설, 지표/단위, 기준 커밋, 동일 입력/부하/빌드/환경, 워밍업/반복/제외 기준을 정하고 기준값부터 측정한다. 같은 조건의 전후 원값, 표본 수, 중앙값/분포, 절대 차이/개선율과 한계를 비교한다. 기준값0/미측정/잡음 범위면 개선율이나 향상을 주장하지 않는다. 테스트 개수와 Gradle 시간은 앱 성능이 아니다.

문서 정리나 동작을 바꾸지 않는 코드 정리는 성능 측정 대상이 아니며 성능 향상을 주장하지 않는다. 실제 측정의 기록과 재현 기준은 [전후 측정 기준](../development/measured-improvements.md)을 따른다.
