# 최초 접수 메일과 첨부 목록 초안

SUB-15의 최초 접수 준비용 초안이다. 참가 형태, 참가 정보, 서명과 최종 첨부는 아직 확정하지 않았다. 입력 칸을 채우고 실제 자료를 확인하기 전에는 발송 가능한 최종본으로 사용하지 않는다. 메일 앱에 초안을 만들거나 발송한 기록도 아니다.

## 수신, 제목과 CC 입력

| 항목 | 사용자 확인 후 입력할 값 |
|---|---|
| 받는 사람 | `appdevchallenge@hyundai-partners.com` |
| 보내는 사람 | `[대표자가 사용할 발신 주소, 비공개 입력]` |
| 참가 형태 | `[개인 또는 팀, 사용자 확정]` |
| 참가명 | `[팀명, 개인이면 성명, 비공개 입력]` |
| 대표자 | `[대표자명, 비공개 입력]` |
| 제목 | `[차량용 앱 개발 공모전] [참가명]_[대표자명]` |
| CC | `[팀원 전원의 주소, 비공개 입력]` |

제목의 공식 형식은 `[차량용 앱 개발 공모전] 팀명(개인은 성명)_대표자명`이다. 참가 형태와 참가명은 사용자가 확인한다. 팀은 대표자가 발송하고 팀원 전원을 CC에 포함한다. 실제 발신 주소와 구성원 정보는 이 공개 문서에 채우지 않는다. 공식 제목의 `[차량용 앱 개발 공모전]` 표시는 유지하고 `[참가명]`과 `[대표자명]` 입력 칸만 실제 값으로 바꾼다. 개인 참가라면 없는 팀원 주소를 임의로 추가하지 않고 본인의 개별 동의서를 확인한다. [공식 제출 안내](https://appdevchallenge.auto-hmg.io/guide/submission), [참가 규정](https://appdevchallenge.auto-hmg.io/guide/rules)

## 복사할 기본 본문

아래 본문은 사용자가 입력 칸과 실제 첨부를 확인한 뒤 사용할 초안이다. 대괄호 입력 칸을 그대로 보내지 않는다. 첨부 파일명은 실제 메일에 넣은 최종 파일과 맞추고, 선택 자료 문단은 제공하기로 확정한 것만 추가한다. 동의서를 접수양식과 같은 파일에 넣었다면 실제 첨부 파일 단위로 목록을 합치고 참가자 전원분의 포함 여부를 확인한다.

```text
안녕하세요.

차량용 앱 개발 공모전에 한길졸업의 참가 신청 자료를 제출하고자 합니다.

참가 형태: [사용자가 확정한 개인 또는 팀]
참가명: [확정한 참가명]
대표자: [대표자명]
앱 이름: 한길졸업

제출 자료 목록
1. [작성과 서명을 확인한 접수양식의 실제 파일명]
2. [참가자 전원의 개별 동의서 실제 파일명 목록]

[제공하기로 확정한 선택 자료 문단을 여기에 추가하거나 이 줄을 삭제]

자료 확인 후 접수 여부를 안내해 주시면 감사하겠습니다.
감사합니다.

[대표자명]
```

## 선택 자료 추가 문단

영상과 소스/APK를 함께 제공하는 GitHub 저장소는 공식 선택 자료다. 준비 중인 파일과 링크를 제출한 것으로 표시하지 않는다. 숏폼은 별도 선택 참여이며 현재 안내의 가산점은 0점이다. 숏폼 게시와 링크 확정은 사용자 작업으로 남긴다. [공식 제출 안내](https://appdevchallenge.auto-hmg.io/guide/submission)

GitHub를 선택할 때 사용할 문단:

```text
참고자료
- 소스 저장소: https://github.com/HanGilLab/Android
- APK 빌드 기준 소스: [최종 APK를 빌드한 Git 태그 또는 커밋 링크]
- 실행 가능한 release APK: [위 소스와 버전을 맞춘 최종 release APK 제공 링크]
```

위 저장소는 실제 공개 소스 주소다. 이 초안에는 제출할 최종 release APK를 연결하지 않았으므로 GitHub 제출 준비 완료를 뜻하지 않는다. GitHub를 제출한다면 실행 가능한 release APK를 저장소의 `apk/`에 제공하고, 용량 제한을 넘으면 Releases를 사용한다. 안내된 파일명 형식은 `팀명_앱이름_release.apk`이며 실제 참가명과 파일명은 최종 확인한다. [공식 제출 안내](https://appdevchallenge.auto-hmg.io/guide/submission)

영상도 제공하기로 확정했다면 필요한 줄만 추가한다.

```text
- 시연 영상: [최종 영상 링크 또는 실제 첨부 파일명]
```

APK는 소스 코드와 함께 GitHub에 제공하는 묶음으로 준비한다. 메일에 APK만 첨부하는 방식으로 이 조건을 대신하지 않는다. [공식 모집 공고](https://appdevchallenge.auto-hmg.io/notice/c0a1a000-2026-4923-8000-000000000001)

## 첨부와 링크 준비 상태

아래 표는 준비 목록이며 첨부 완료 목록이 아니다. 선택 자료라는 이유로 프로젝트의 release APK와 영상 준비 목표를 완료하거나 제외하지 않는다.

| 구분 | 자료 | 현재 상태와 최종 확인 |
|---|---|---|
| 필수 | 접수양식 | 참가 정보, 심사용 본문과 서명 확정 미확인. 최종 파일의 열림과 입력 내용을 확인한다 |
| 필수 | 참가자 전원의 개별 동의서 | 구성원 수, 개인별 작성과 서명 미확인. 전원분을 빠짐없이 준비한다 |
| 선택 | 시연 영상 | 제공 여부와 최종본 미확인. 실제 재생과 제출 앱 버전의 일치를 확인한다 |
| 선택 | GitHub 소스와 대응 release APK 묶음 | 공개 소스 주소는 위에 기재했다. 같은 제출 버전의 소스와 실행 가능한 release APK 제공은 미확인이다. 파일명, 링크 접근과 설치/실행을 확인한다 |
| 별도 선택 | 숏폼 | 참여와 게시 링크 미확인. 사용자가 게시 여부를 결정한다 |

필수 서류만으로도 지원할 수 있다는 공식 안내와 프로젝트의 전체 준비 목표는 구분한다. 현재 SUB-06과 SUB-14 등 선행 자료가 미완료여서 SUB-15 전체는 미체크로 유지한다. 초안 작성으로 제목/CC 확인, 실제 발송 또는 접수 확인을 완료하지 않는다. [공식 제출 안내](https://appdevchallenge.auto-hmg.io/guide/submission)

## 사용자의 발송 전 확인

- [ ] 최초 제출인지 확인했다. 이미 제출했다면 [수정 제출 절차](revision-checklist.md)를 따른다.
- [ ] 참가 형태와 참가명, 대표자, 발신 주소, 공식 수신 주소와 제목을 확인했다.
- [ ] 팀원 전원의 CC와 참가자 전원의 개별 동의서를 확인했다.
- [ ] 접수양식과 동의서의 실제 입력, 동의와 서명을 직접 확인했다.
- [ ] 본문의 입력 칸을 모두 정리하고 첨부 목록을 실제 최종 파일과 맞췄다.
- [ ] 제공할 선택 자료만 남기고, 링크 접근과 영상 재생을 실제 최종본으로 확인했다.
- [ ] GitHub를 제출한다면 링크의 태그 또는 커밋이 APK 빌드 원본을 가리키는지 확인했다. 다운로드한 APK와 배포 전에 확인한 APK의 SHA-256이 같은지 대조하고, 해당 APK를 설치해 실행했다.
- [ ] 심사용 자료에서 연락처, 비공개 주소, 실제 위치와 원문 로그를 점검했다. 운영 접수 정보와 서명은 비공개 제출본에서 관리한다.
- [ ] 대표자가 발송할 최종 묶음과 시점을 확인했다.

서명과 실제 발송은 사용자가 수행한다. 발송 뒤에는 사용자가 발송본, 첨부 버전과 발송 시각을 비공개로 보관하며, 접수 확인은 발송 사실과 별도로 기록한다. 사용자 확인 전에는 SUB-17과 SUB-18을 완료로 표시하지 않는다.
