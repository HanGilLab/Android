# 수정 제출 절차와 확인표

SUB-19는 수정 제출에 필요한 절차를 준비하는 항목이다.
최초 발송이나 수정 발송을 실행·확인한 것으로 계산하지 않는다. 실제 발송과 접수 확인은 SUB-17·18에서 따로 관리한다.
현재 참가 정보, 발송 이력과 수정 필요 여부는 사용자 확인 전이다.

## 현재 확인 상태

| 확인 항목 | 현재 상태 | 확인 담당 |
|---|---|---|
| 최초 제출 메일을 실제 발송했는가 | 미확인 | 대표자·사용자 |
| 최초 발신 주소와 참가 정보가 맞는가 | 미확인 | 대표자·사용자 |
| 수정 대상과 제출 자료 버전이 무엇인가 | 미확인 | 사용자 |
| 수정 제출이 필요한가 | 미확인 | 사용자 |
| 실제 수정 발송을 승인·실행했는가 | 미확인 | 대표자·사용자 |
| 발송본·첨부 버전과 접수 확인을 보관했는가 | 미확인 | 대표자·사용자 |

실제 주소·구성원 정보·서명·발송 원문은 공개 문서에 적지 않고 비공개로 관리한다.
공유 체크리스트에는 확인 여부와 필요한 조치만 남긴다.

## 수정 필요 여부 결정

- 최초 발송이 확인되지 않았다면 수정 제출로 추정하지 않는다. 먼저 최초 제출 여부를 사용자에게 확인한다.
- 최초 발송을 하지 않은 것으로 확인되면 최초 접수 절차(SUB-15~18)로 준비한다.
- 이미 발송했다면 사용자가 수정 대상과 버전을 확인하고 `필요 / 불필요 / 미확인` 중 하나로 기록한다.
- 필요 여부가 미확인이면 발송하지 않는다. 불필요로 확인되어도 실제 발송·접수 상태를 별도로 확인한다.

## 수정 제출 순서

1. 대표자가 최초 제출에 사용한 발신 주소를 비공개 발송본에서 확인한다. 수정 메일도 같은 주소를 사용한다.
2. 수정한 접수양식과 전체 제출 자료를 한 묶음으로 준비한다. 서명한 참가자 전원의 동의서도 함께 다시 첨부한다.
   변경된 파일만 보내는 방식으로 전체 제출 묶음을 대신하지 않는다.
3. 영상·GitHub·APK 등 선택해 제출할 참고자료의 파일·버전·링크를 맞춘다. 문서 열림·링크 접근·APK 설치·영상 재생은 실제 제공할 최종본으로 확인한다.
4. 수신자는 공식 접수 주소 `appdevchallenge@hyundai-partners.com`, CC는 팀원 전원으로 확인한다. 실제 주소 목록은 사용자가 비공개로 점검한다.
5. 제목은 다음 형식을 사용한다.

   `[수정제출] [차량용 앱 개발 공모전] 팀명(개인은 성명)_대표자명`

6. 사용자가 수정 필요 여부·전체 첨부·제목·발신 주소·전원 CC를 최종 확인한 뒤 대표자가 마감 전에 발송한다.
   자동화는 서명을 대신하거나 실제 메일을 보내지 않는다.
7. 대표자가 실제 발송본과 전체 첨부 버전·발송 시각을 비공개로 보관하고 발송 사실을 확인한다. 접수 확인 여부는 별도로 기록한다.
   여러 번 발송한 경우 마감 전 마지막 제출본이 심사본이므로, 해당 발송본과 제출 자료가 같은지 확인한다.

위 순서의 발신 주소·전체 재첨부·제목·CC·최종본 기준은 [공식 참가 규정](https://appdevchallenge.auto-hmg.io/guide/rules)과
[지원·제출 안내](https://appdevchallenge.auto-hmg.io/guide/submission)에 따른다. 확인일은 2026-10-28이다.

## 대표자 발송 전 확인표

아래 항목은 실제 제출 시 사용자가 확인한다. 절차 문서가 준비됐다는 이유로 체크하지 않는다.

- [ ] 최초 제출 여부와 수정 필요 여부를 사용자에게 확인했다.
- [ ] 최초 발신 주소와 같은 주소를 사용한다.
- [ ] 최신 접수양식과 전체 제출 자료, 참가자 전원의 서명 동의서를 다시 첨부했다.
- [ ] 선택 제출 자료의 파일·버전·링크가 같은 제출본을 가리킨다.
- [ ] 공식 수신 주소·팀원 전원 CC·수정 제출 제목을 확인했다.
- [ ] 대표자가 실제 발송할 최종 묶음과 발송 시점을 확인했다.
- [ ] 실제 발송 후 발송본·첨부 버전·발송 시각을 보관했다.
- [ ] 접수 확인 여부를 실제 발송 사실과 구분해 기록했다.

## 일정과 완료 범위

우리 준비 목표는 2026-11-10 한국 시간이며, 공식 접수 마감은 2026-11-15 23:59다.
마감 시각은 [공식 접수양식](https://appdevchallenge.auto-hmg.io/downloads/contest-application-consent.docx)에서 확인했다.
접수 기한이 남아 있어도 개발 자동화를 연장하지 않는다.

SUB-19의 완료는 이 절차와 현재 필요 여부 상태를 마련하고 검토하는 것이다.
참가 정보 확정·개별 서명·전체 자료 완성·실제 메일 발송·접수 확인은 각각의 미완료 항목과 사용자 작업으로 유지한다.
